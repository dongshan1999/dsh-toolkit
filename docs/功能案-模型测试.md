# 功能案：模型测试（components/model-test）

> 状态：已实现
> 关联组件：`components/model-test/`（host.js + client.js + README.md）
> 同步维护：本文与 `components/model-test/README.md` 保持一致，改动时请同时更新。
> 面板位置：侧边栏「工具集」（order 48）→ 分页「模型测试」（order 51）

## 1. 要解决的问题

「DSH 自己配置的模型到底能不能连通、有多快」原本没有统一的观测手段：只能开一轮真实对话，凭感觉判断，
读数无法并排比较，失败也说不清是凭证、路由还是网关的问题。本组件把这件事变成面板里的一次点击，
并支持三种粒度：

- **全部** —— 一次跑完当前可路由的所有模型；
- **单个组** —— 只测某个 provider 下的全部模型；
- **单组单模型** —— 只测某个 provider 下的某一个模型。

参数是第二个问题。DSH 的 `ctx.llm.stream()` 只认 `temperature` / `maxTokens` / `reasoningEffort` 三个可调参数，
而每个模型能不能发 `temperature`、有哪些思考档位、上下文与输出上限是多少，都得逐个查文档；填错不是被忽略，
而是直接报错（DSH 对非法档位抛 `UNSUPPORTED_REASONING_EFFORT`，不 clamp 不 alias）。
本面板按模型名自动推断参数：内置 100+ 主流模型族的
`temperature / maxTokens / temperature 支持性 / 思考档位 / 上下文与输出上限`，
打开面板就能看到每个模型命中哪一族、下次测试会发什么参数，也可以逐模型或整组手工覆盖，
或一键从 [models.dev](https://models.dev) 同步最新快照。

第三个问题是**归因**。只看结果看不出发了什么参数、参数从哪来；所以每条结果都带
`params`（实际发出的值 + 来源 + 安全阀调整说明）。

第四个问题是**落点混淆**。面板上有两个看起来都在「配参数」的区块：插件的 `params.json` 只影响「测试」发出的请求，
DSH 的 `cordis.patch.yml` 才影响真实对话，两者字段与能力都不同（详见 4.5）。不把边界写清楚，
用户很容易以为在面板里配完 temperature 就改变了真实对话。

## 2. 目标与非目标

### 目标

- 按 DSH 运行时真实目录列出「组 → 模型」，组 = 已注册 route，模型 = 逐组 `listModels()`。
- 三种粒度跑测试：全部 / 整组 / 单组单模型；单测只**合并**读数，不冲掉其它模型的结果。
- 每行给出可比较的读数：连接状态、首字延迟、tok/s、输出 tokens、总耗时；失败/超时/中断分别归因。
- 按模型名自动推断参数（内置精选表 + models.dev 同步），并允许逐模型、逐组、本次调用三级覆盖。
- 安全阀：测试前读适配器真实能力，绝不硬发模型不接受的参数，每次调整写进 `note`。
- models.dev 一键同步：只挑当前目录在用的模型，结果落 `presets.json`，覆盖同 id 内置条目。
- 生成可直接粘进 `cordis.patch.yml` 的 `llm-pi-ai.providers.<id>.models` YAML 片段。
- 读 / 写 DSH 真实模型配置：`GET /dsh` 做逐字段 diff，`POST /dsh` 以 `fill` / `replace` 写入。

### 非目标

- 不做模型配置源。面板不含任何模型配置，只读 DSH 运行时正在路由的东西；组与模型都来自
  `ctx.llm.listProviders()` / `ctx.llm.listModels()`。
- 不接触密钥，不引入第二套地址配置。凭证解析、路由选择、重试策略全部由 DSH 负责。
- 不代理真实对话。本组件只发测试请求，聊天仍走 DSH 自己的适配器链路。
- 不列 `listConfigurableProviders()` 里的休眠条目。它们可能没有激活的适配器 route，测了只会得到
  `NO_ADAPTER` 一类噪音错误；该接口只用来补显示名（`displayName`）。
- 不探测 `temperature`、真实 `contextWindow`、`maxTokens` 上限。网关不提供可问的接口，聚合网关
  还会静默忽略未知参数；这几项只能读适配器声明（`resolveModelInfo`，见 §5.4）或 models.dev 预设表。
- 不部署 `client.js` 源码。面板源码由根目录 `node build.mjs` 包装进统一入口。

## 3. 关键约束（决定了方案形状）

### 3.1 组件文件

| 文件 | 职责 |
|---|---|
| `host.js` | 目录构造 + 参数推断 + 探测逻辑 + 经 `ctx.connection.fetch.register` 注册路由 |
| `presets.js` | 预设库（读内置表/同步结果）+ 参数分层解析 + 安全阀 + YAML 片段生成。纯函数，无 `ctx` 依赖 |
| `presets-data.mjs` | **内置精选表**（主流模型族的参数快照，随仓库发布、离线可用） |
| `dsh-config.js` | 读写 DSH 真实模型配置（Host 侧，无副作用） |
| `client.js` | 浏览器面板源码。**不直接部署**：由根目录 `node build.mjs` 包装进统一入口 `client.js` |

### 3.2 约束表

| # | 约束 | 依据 | 后果 |
|---|---|---|---|
| C1 | 目录来自 DSH，不来自本插件 | 组 = `ctx.llm.listProviders()` 返回的**已注册 route**（`dl`、`xiaomi` 这类）；只有真正激活的 route 才发得出请求 | 未激活 / dormant 的配置不会被假装成可测；`listConfigurableProviders()` 只用于补 `displayName` |
| C2 | 测试调用必须与真实对话同一条链路 | 用 `ctx.llm.stream({ provider, model, messages, maxTokens, signal })`，凭证解析、路由选择、重试策略都由 DSH 负责 | 「连通性」结论与真实对话一致；面板不接触任何密钥 |
| C3 | 测试是**真发一次推理请求**，会计费 | 与 image-gen 的「测试」按钮不同：那个只 `GET /models`、不扣费 | `maxTokens` 默认压到 256，prompt 默认是一段「测速」重复词（纯文本产出最稳定，便于比较 tok/s），但仍然真实计费 |
| C4 | 可调参数只有三个 | `ctx.llm.stream()` 只认 `temperature` / `maxTokens` / `reasoningEffort`；`stop` 被 `llm-pi-ai` 适配器显式拒绝：`llm-pi-ai does not support GenerateOptions.stop` | 参数面就这三个字段，多一个都没有 |
| C5 | DSH 对非法思考档位**直接抛错** | `UNSUPPORTED_REASONING_EFFORT`，不 clamp 不 alias | 测试前必须 `ctx.llm.resolveModelInfo(provider, model)` 查 `reasoning.efforts` / `defaultMaxTokens`，自己拦 |
| C6 | 路由表按 path 去重 | 同 path 注册两次会被判 `already registered` | `GET` 与 `POST` 共用 `/api/model-test/config` 一条 route，按 `request.method` 分流；`/dsh` 同理 |
| C7 | 某组 `listModels()` 抛错不能拖垮整个目录 | 逐组独立 try/catch | 失败进 `failures` 单独展示，不影响其它组（例如某个网关没配好） |
| C8 | 面板源码不直接部署 | 根目录 `node build.mjs` 负责包装 | 改 `client.js` 后必须重新跑 build，否则面板不更新 |
| C9 | 两个「配参数」区块落点完全不同 | 插件 `params.json` vs DSH `cordis.patch.yml`；DSH 无模型级 `temperature` 槽位 | 面板必须分两块展示，并逐字段说明谁能写 `temperature`（见 4.5） |

## 4. 数据模型与数据落点

### 4.1 目录：组 → 模型

`GET /api/model-test/catalog` 返回：

```ts
{
  ok: true,
  generatedAt: number,
  groups: [{
    id: string,                 // provider id，如 'dl'
    name: string,               // 显示名，来自 listConfigurableProviders().displayName
    models: [{
      id: string,
      name: string,
      inputModalities: string[],
      preset: object | null,    // 命中的预设族
      paramsOverride: object | null
    }]
  }],
  failures: [{ id, name, message }],   // 某组 listModels 抛错时单列
  providerCount: number,
  modelCount: number,
  declared: number,             // listConfigurableProviders() 的条目数（对照用）
  overrides: object,            // params.json 里的手工覆盖
  presets: { ...meta, overridden },    // 预设库元信息
  files: { params: string, presets: string }
}
```

构造顺序（`buildCatalog`）：先取 `listProviders()` 拿已注册 route，逐组 `await ctx.llm.listModels(provider)`，
再逐模型匹配预设与手工覆盖。`listProviders()` 抛错时整份目录退化为单个 `failures` 条目，`declared` 仍如实记录。

### 4.2 参数分层解析（逐字段取值，先命中先用）

| 优先级 | 来源 | 存在哪 |
| --- | --- | --- |
| 1 | **本次指定** `run` 的 `targets[].params` / `body.params` | 一次性，不落盘 |
| 2 | **单模型覆盖** | `params.json`，键 `provider\0model` |
| 3 | **整组默认** | `params.json`，键 `provider\0*` |
| 4 | **预设命中** | `presets-data.mjs` 内置表 + `presets.json` 同步结果 |
| 5 | **全局默认** | 面板顶部的「默认 temperature / 默认档位」 |

每个字段**独立**取值：比如手工只配了 `temperature`，`reasoningEffort` 仍会从预设取。
最终每个字段都会带一个来源标签：`target | override | group | preset | default`。

### 4.3 预设族

`presets-data.mjs` 收录 100+ 个主流模型族（OpenAI / Anthropic / Google / DeepSeek /
Qwen / GLM / Kimi / MiniMax / Grok / Mistral / Llama / 豆包 / 混元 / 阶跃 / 文心 / 百川 / 零一 等），
按 `id → 别名 → 正则` 三级匹配，**纯本地匹配、零网络**。每族记录：

```
label / vendor / matches[] / supportsTemperature / reasoning{mode,levels,default,wire} /
contextWindow / maxTokens / suggest{temperature,maxTokens,reasoningEffort} / note
```

### 4.4 指标口径

| 指标 | 口径 |
| --- | --- |
| `ttftMs`（首字延迟） | 首个 `text-delta` / `reasoning-delta` 到达时间；没有文本分片时退化为**首个分片**到达时间 |
| `tokensPerSecond` | `outputTokens ÷ 总耗时`，与网关「输出 TPS」同一口径；没有输出 token 时为 `null` |
| `totalMs` | 从发起 `stream()` 到流结束的总耗时 |
| `streamMs` | `totalMs - ttftMs`，即真正用于产出 token 的时间 |
| `ok` / `status` | `finish.reason.kind` 为 `stop` / `max-tokens` / `tool-calls` → `ok`；`error` / `aborted` → 失败 |

判定细节：

- **超时归因**：`timeoutMs` 到点即 `abort()`，并额外 `iterator.return()` 收尾；
  即使适配器不响应 abort，也有 `timeoutMs + 5s` 的硬超时兜底，
  结论归到 `超时`（`status: 'timeout'`）而不是笼统的失败。
- **连接成功但无输出**（例如全部命中缓存、或模型只回空串）仍算 `连接正常`，只是速度显示 `-`。
- **失败信息透传**：优先取 `finish.reason.failure.message`（含 provider 原始报错与 HTTP 状态）。
- 并发默认 3；一次「测试全部」的总时长约等于 `模型数 ÷ 并发 × 单次耗时`。

### 4.5 两个参数落点（最容易踩的地方）

| 区块 | 落到哪里 | 影响谁 | 能写 `temperature` 吗 |
| --- | --- | --- | --- |
| `参数`（上半） | 插件自己的 `params.json` | 只影响点「测试」发出的请求 | 能（每次调用参数） |
| `DSH 配置`（下半） | `cordis.patch.yml` 的 `llm-pi-ai.providers.<组>.models[]` | **真实对话** | 不能（DSH 无模型级槽位；`compat.supportsTemperature: false` 只在 `anthropic-messages` 协议下合法） |

`DSH 配置` 区先 `GET /api/model-test/dsh` 读取运行时合并后的真实字段，与预设建议逐字段
diff（`changed` / `before` / `after`），再按 `fill`（只补缺失）或 `replace`（覆盖差异）写入。
写入由 DSH 的 `configEditor` 承担：文件锁、保留 `!!js` 标签与注释、schema 校验、原子写、
Loader 热重载、失败自动回滚；写后立刻回读，`before / after` 是磁盘真值而不是回声。

`compat` 是**逐键**比较、逐键写入的（`set compat.<键>`，只写有差异的键），不会整块替换，
所以内置 catalog 带下来的 `chatTemplateKwargs` / `chatTemplateArgs` 不会被覆盖丢；schema
物化出来的空 `{}` 视为「没配」，既不显示也不算差异。`compat.supportsTemperature` 只对
`anthropic-messages` 协议 offer，面板按 provider 的 `api` 过滤，其它协议不产出这一项。

### 4.6 落盘位置

| 文件 | 内容 | 环境变量覆盖 |
| --- | --- | --- |
| `$DSH_HOME/dsh-toolkit/model-test/params.json` | 手工覆盖（逐模型 + 整组） | `MODEL_TEST_PARAMS` |
| `$DSH_HOME/dsh-toolkit/model-test/presets.json` | models.dev 同步结果 | `MODEL_TEST_PRESETS` |

- 写入走 `mkdirSync + tmp + renameSync` 原子替换。
- `DSH_TOOLKIT_DATA` 可整体改道（自检用）。
- `presets.json` 的结构为 `{ version, at, source, total, matched, families[] }`；内置表不落盘，随代码发布。

## 5. 接口契约

所有路由前缀 `/api/model-test/`，经 `ctx.connection.fetch.register` 注册。
成功响应 `{ ok: true, ... }`；失败统一 `{ ok: false, code: 'model-test/<reason>', message }` 并带对应 HTTP 状态。

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/model-test/catalog` | 目录：`{ ok, generatedAt, groups: [{ id, name, models: [{ id, name, inputModalities, preset, paramsOverride }] }], failures, providerCount, modelCount, declared, overrides, presets, files }` |
| `POST /api/model-test/run` | 跑测试，见 5.1 |
| `GET /api/model-test/presets` | 预设库：`{ meta, aliases, builtin[], synced[], files, thinkingLevels }` |
| `POST /api/model-test/presets/sync` | 按当前目录的模型从 models.dev 同步，落 `presets.json` |
| `GET /api/model-test/config` | 读手工覆盖：`{ overrides, file }` |
| `POST /api/model-test/config` | 写手工覆盖：`{ entries: [{ provider, model, params }] }`（`model: '*'` = 整组；三字段全 `null` = 删除） |
| `POST /api/model-test/inspect` | 单模型画像：`{ provider, model }` → `{ preset, live, overrides, params, snippet, thinkingLevels }` |
| `GET /api/model-test/dsh?provider=P&model=M` | 读 **DSH 真实配置**里该模型的字段（`current`）+ 预设建议（`proposed`）+ 逐字段 `diff` + 写入计划 `plan`；`available/reason` 说明这个 provider 能不能写 |
| `POST /api/model-test/dsh` | 把字段写进 DSH 配置：`{ provider, model, mode: 'fill' \| 'replace', revision? }`。`fill` 只补缺失字段，`replace` 用建议值覆盖差异字段 |

> `GET` 与 `POST` 共用 `/api/model-test/config` 一条 route（按 `request.method` 分流）：
> 路由表按 path 去重，同 path 注册两次会被判 `already registered`。`/dsh` 同样共用一条 route。

### 5.1 `POST /api/model-test/run`

入参：

| 字段 | 说明 |
| --- | --- |
| `targets` | `[{ provider, model }]`，精确指定多条（优先级最高） |
| `provider` | 只测该组（不带 `model` 即整组） |
| `provider` + `model` | **只测该组单个模型** |
| `timeoutMs` | 默认 `120000`，clamp 到 1000–180000 |
| `maxTokens` | 默认 `256`，clamp 到 1–1024 |
| `concurrency` | 默认 `3`，clamp 到 1–8 |
| `prompt` | 默认「请连续输出 80 个「测速」…」，trim 后截断 200 字符 |
| `params` | 本次指定 `{ temperature, maxTokens, reasoningEffort }`，优先级最高（`targets[].params` 更细） |
| `targets[].params` | 逐目标的本次参数 |

返回 `{ ok, startedAt, finishedAt, options, catalog, summary, results }`，`results[]` 每项：

```
{ provider, providerName, model, modelName, ok, status, finishKind, message,
  ttftMs, totalMs, streamMs, outputTokens, usage, tokensPerSecond,
  params: { temperature, maxTokens, reasoningEffort, source, sourceLabel, note, preset }, at }
```

`params` 是**实际发出的**参数与来源（`target | override | group | preset | default`），
`note` 记录安全阀的每一次调整（如「该模型不支持 极高(xhigh)，已改用 中(medium)」）。
`status ∈ ok | error | timeout | aborted`。

没匹配到任何目标时**不空跑**，直接 `400` + `model-test/no-target`。

### 5.2 预设库与同步

`GET /api/model-test/presets` 返回 `{ ok, generatedAt, meta: { ...内置 meta, syncedAt, syncedCount }, aliases, builtin[], synced[], files: { params, presets }, thinkingLevels }`。

`POST /api/model-test/presets/sync`：先读当前目录里的模型列表，再从 `https://models.dev/api.json`
只挑这些在用模型写进 `presets.json`（原生厂商优先于聚合商；过滤 deprecated 与非文本模型；
同归一化 id 去重）。同步结果按 id **覆盖**内置表同 id 条目，其余内置族照常生效。

- 地址可用 `MODELS_DEV_API_URL` 覆盖（内网镜像/离线测试）。
- 同步是**只读拉取**：一次 `GET`（带 `accept: application/json`），不携带本地配置或密钥。
- 拉取超时 20 秒；返回 `{ ok, count, at, message, meta, files: { presets } }`。

### 5.3 手工覆盖

| 方法 | 请求 | 返回 |
|---|---|---|
| `GET` | — | `{ ok, generatedAt, overrides, file }` |
| `POST` | `{ entries: [{ provider, model, params }] }` | `{ ok, overrides, file, generatedAt }` |

- `model: '*'` 表示整组默认。
- `params` 三个字段全 `null` = 删除该条覆盖。
- `entries` 不是数组或条目非法 → `400` + `model-test/config-invalid`。

### 5.4 单模型画像

`POST /api/model-test/inspect`，请求 `{ provider, model, params?, fallback? }`，返回：

```
{ ok, provider, model,
  preset,                    // 命中的预设族
  live,                      // 适配器真实能力（resolveModelInfo）
  overrides: { model, group },
  params: { temperature, maxTokens, reasoningEffort, source, sourceLabel, note },
  snippet,                   // 可直接粘进 cordis.patch.yml 的 YAML
  thinkingLevels,
  files: { params, presets } }
```

缺 `provider` 或 `model` → `400` + `model-test/inspect-invalid`。

### 5.5 生成 YAML 片段

模型行 → `参数` → `生成 YAML 片段`：读适配器真实能力，产出可直接粘进
`cordis.patch.yml` 的 `llm-pi-ai.providers.<id>.models` 条目：

```yaml
- id: gpt-6-sol
  name: GPT-6 Sol
  contextWindow: 400000
  maxTokens: 8192
  input: [text]
  reasoningEfforts: { low: low, medium: medium, high: high }
  compat: { supportsTemperature: false }
```

这样接第三方 API 时不必再逐个查文档填参数。

### 5.6 错误码

- `400` + `model-test/no-target` —— 没匹配到任何目标（不空跑）。
- `503` + `model-test/llm-unavailable` —— `ctx.llm.stream` 不可用。
- `400` + `model-test/config-invalid` —— `entries` 不是数组 / 条目非法。
- `400` + `model-test/inspect-invalid` —— `inspect` 缺 `provider` 或 `model`。
- `502` + `model-test/presets-sync-failed` —— models.dev 拉取或匹配失败。
- `500` + `model-test/catalog-failed` / `model-test/run-failed` / `model-test/presets-failed` / `model-test/config-failed` / `model-test/inspect-failed` —— 未预期异常。
- `503` + `model-test/dsh-unavailable` —— `ctx.get('settings')` 不可用（DSH 版本没暴露配置写入通道）。
- `400` + `model-test/dsh-invalid` —— `/dsh` 缺 `provider`（POST 还要求 `model`）。
- `400` + `model-test/dsh-unavailable`（写时）—— 目标 provider 没在配置里声明 `models`（用内置目录 + `modelOverrides` 的形态不能直接写 `models`，会把目录缩成一个模型）。
- `409` + `model-test/dsh-conflict` —— 读完之后 DSH 配置被别人改过，`revision` 已过期；DSH 的 `settings` 用 CAS 拒绝这次写入，不会覆盖别人的改动。重新读取后再写即可。
- `500` + `model-test/dsh-write-failed` —— `settings.mutate` 抛错（DSH 侧已自动回滚原文件）。

代码里另有几条路由级错误码：`500` + `model-test/dsh-failed`（`/dsh` 未预期异常）、
`400` + `model-test/no-target`（`run` 匹配不到模型）、`400` + `model-test/params-invalid`（参数不合法）。

## 6. 面板与交互

> 位置：侧边栏「工具集」（order 48）→ 分页「模型测试」。合并前是独立的侧边栏入口（order 51），
> 面板 key 仍是 `model-test`，`ctx.layout.selectPanel('model-test')` 照样能直接打开。

- 顶部 `测试全部` 一键跑完目录里所有模型；`刷新目录` 重新读取 DSH 的组与模型。
- 参数行（测试中禁用）：
  `超时`（15/30/60/120/180 秒）、`输出上限`（16/64/256/512 tokens）、
  `并发`（1/2/3/5/8）、`默认 temperature`、`默认档位`、`提示词`。
- **每个组头**：整行是折叠热区（`▸/▾` + 组名 + `N 个模型`）+ `整组参数` + `测试本组` → **整组**。
- **每个模型行**：状态点 + 模型名/ID + 实时读数 + 右侧 `测试` 按钮 → **单个组下单个模型**。
- **每个模型行**：模型名后跟一行参数徽标 ——
  `预设族名`（命中内置表/models.dev）+ `已配置`（有手工覆盖）+
  生效参数摘要（`t=0.6 · max=64 · 中`，优先显示上次测试**真实发出**的值）。
  右侧 `参数` 按钮展开编辑区。
- 有结果时顶部出现汇总卡：`成功 x / y`、`平均首字`、`平均速度`、`最快 / 最慢`。
- 单测某个模型时**合并**而非覆盖已有读数，其它模型上一次的结果仍留在表里。
- 组默认全部收起（只显示组名与模型数）；点组头任意空白处展开，再点收起。
- 收纳统一走组头：点组头任意空白处展开/收起这一组，没有全局「收起全部 / 展开全部」按钮。
  组头里的按钮（`整组参数` / `测试本组`）不触发切换；收起状态下点 `测试本组` 会先展开该组再跑。
  折叠只影响渲染，不影响「测试本组」——收起的组照样能整组测。

每行读数形如：

```
连接正常 · 首字 420 ms · 46.4 tok/s · 64 tokens 输出 · 总 1.80 s
失败：HTTP 401 unauthorized
超时：超过 120000ms 未返回
已中断：请求被中断
```

参数编辑区（点 `参数` 展开）提供：预设族名、适配器真实档位、生效参数与来源、安全阀 `note`、
`生成 YAML 片段`，以及下方的 `DSH 配置` 区（只读 `current`、逐字段 diff、`fill` / `replace` 写入按钮）。

### 6.1 安全阀（绝不硬发模型不接受的参数）

预设只是**推荐值**，能不能发以适配器真实能力为准 —— 测试前会调
`ctx.llm.resolveModelInfo(provider, model)` 拿 `reasoning.efforts` / `defaultMaxTokens`：

- **档位不在能力里** → 退到 `defaultEffort`（或最低档），`note` 写明「该模型不支持 X，已改用 Y」。
  DSH 侧对非法档位是**直接抛错**（`UNSUPPORTED_REASONING_EFFORT`），不 clamp 不 alias，所以必须在这里拦。
- **预设标记 `supportsTemperature: false`**（o 系列、gpt-5/6 多数、claude-5 系、kimi-k3、
  MiniMax-M3.1-Flash 等）→ `temperature` 一律不发。
- **`maxTokens` 超过适配器 `defaultMaxTokens`** → 收顶并说明。
- **测速专用收顶**：预设建议的 `8192/16384` 是给真实对话用的输出上限，
  测速照发会白烧几千 tokens，所以测试时一律按顶部「输出上限」收顶。

能力探测失败（老适配器没有 `resolveModelInfo`）不会让测试失败，只是退回预设推断。

## 7. 安全与隐私

1. **不接触密钥。** 面板与路由都不读凭证；凭证解析、路由、重试全在 DSH 适配器里完成，
   插件也没有第二套地址配置。
2. **真实计费的边界写清楚。** 「测试」会真的调模型：默认 `maxTokens=256`，整批测试按并发跑完一组
   就是一组真实请求；面板与文档都明确标注，避免被误当成 image-gen 那种不扣费的探活。
3. **只落参数，不落密钥。** `params.json` / `presets.json` 只存 `temperature` / `maxTokens` /
   `reasoningEffort` 与预设快照。
4. **数据目录可改道。** `MODEL_TEST_PARAMS` / `MODEL_TEST_PRESETS` 改路径，`DSH_TOOLKIT_DATA`
   整体改道，自检据此不碰真实数据。
5. **同步是单向只读。** 从 models.dev 只发一次 `GET`，不携带本地配置或密钥；地址可由
   `MODELS_DEV_API_URL` 指向内网镜像。
6. **DSH 配置写入不碰 YAML 文本。** 走官方 `settings.mutate`：文件锁、保留 `!!js` 标签与注释、
   schema 校验、原子写、Loader 热重载、失败回滚全由 DSH 负责。
7. **并发写有 CAS 保护。** `revision` 过期时返回 `409 model-test/dsh-conflict`，不会覆盖别人的改动；
   写后立刻回读，`before / after` 是磁盘真值。
8. **不嗅探、不代理。** 除测试/同步这两类显式动作外，不发起任何网络请求。

1. 语法检查通过：

   ```bash
   node --check components/model-test/host.js
   node --check components/model-test/presets.js
   node --check components/model-test/client.js
   ```

2. 面板构建通过（`client.js` 源码不直接部署）：

   ```bash
   node build.mjs
   ```

3. 自检全绿：

   ```bash
   node tools/check-client.mjs
   ```

   其中 `model-test` 两组断言至少覆盖：面板注册与 `ctx.layout.selectPanel('model-test')`；
   `GET /catalog` 与 `POST /run` 已注册；三种粒度入口（全部 / 整组 / 单组单模型）；
   匹配不到目标时 `400 + model-test/no-target`；`timeoutMs` / `maxTokens` 的 clamp；
   手工覆盖写入后目录与测试结果随之变化、`params: null` 能清除；
   `resolveModelInfo` 不可用时降级到预设推断；`inspect` 缺字段返回 `400 + model-test/inspect-invalid`。

4. 路由冒烟（把 `<DSH 端口>` 换成本地实际端口）：

   ```bash
   curl -s 'http://127.0.0.1:<DSH 端口>/api/model-test/catalog'
   curl -s -X POST 'http://127.0.0.1:<DSH 端口>/api/model-test/run' \
     -H 'content-type: application/json' \
     -d '{"provider":"<组>","model":"<模型>","timeoutMs":30000,"maxTokens":32}'
   ```

   期望：`catalog.ok === true`，`groups[].models[]` 带 `preset`；
   `run` 返回的 `results[].params.source` 与 `note` 能对应上实际发出的参数。

5. 面板在「工具集」壳里作为分页出现，标签「模型测试」、order 51；合并前的独立入口不再单独出现。
6. 单测一个模型后，其它模型上一次的读数仍在；整组测试在组折叠状态下也能执行。
7. 预设同步：`POST /api/model-test/presets/sync` 后 `presets.json` 出现 `families[]`，
   内置表未命中的族仍照常生效；`MODELS_DEV_API_URL` 指向不可达地址时返回 `502`。
8. 自检**不写真实数据**：`DSH_TOOLKIT_DATA` 重定向到沙箱，`params.json` / `presets.json` 不落在真实
   `$DSH_HOME`。

## 9. 已知限制

- **只测已注册 route。** `listProviders()` 之外的休眠配置不可测；面板不把它伪装成可测，
  `listConfigurableProviders()` 只用来补显示名。这也意味着目录随时可能随 profile 变化。
- **单组失败不影响其它组**，但失败细节只在 `failures` 里展示，不会展开成可重试的独立任务。
- **DSH 无模型级 `temperature` 槽位**，`compat.supportsTemperature` 只在 `anthropic-messages` 协议下合法，
  面板按 provider 的 `api` 过滤，所以大多数 provider 看不到这一项。
- **provider 未在配置里声明 `models` 时不能直接写。** 内置目录 + `modelOverrides` 的形态写 `models`
  会把目录缩成一个模型，因此返回 `400 model-test/dsh-unavailable`。
- **写入依赖 `settings` 服务。** 老版本 DSH 没暴露配置写入通道时，`/dsh` 返回 `503 model-test/dsh-unavailable`；
  并发修改会以 `409` 拒绝，需要重新读取再写。
- **超时兜底有上限。** 适配器不响应 `abort()` 时靠 `timeoutMs + 5s` 的硬超时收尾，结论标记为 `timeout`。
- **测速输出被收顶。** 预设建议的 8192/16384 不会照发，测试一律按面板「输出上限」截断（clamp 1–1024），
  所以测得的 tok/s 是短输出下的值。
- **一次「测试全部」的耗时**约等于 `模型数 ÷ 并发 × 单次耗时`；并发上限 8，模型多时仍是分钟级。
- **models.dev 同步依赖外部服务。** 拉取失败不影响已同步结果与内置表；地址可用 `MODELS_DEV_API_URL` 覆盖。
- **面板源码改动必须重新 build。** `components/model-test/client.js` 不直接部署，改完不跑 `node build.mjs`
  则界面不变。
