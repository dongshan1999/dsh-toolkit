# 功能案：插件、配置与会话的迁移备份（components/backup）

> 状态：**封存**（2026-10-22 决定暂不实现，方案留档）
> 封存原因：优先级让给会话注释功能；本文只作设计参考，不代表待办。
> 关联组件：`components/backup/`（新建）、`components/toolkit/`（壳内置分页）
> 面板位置：toolkit 分页「备份」（order 55）
> 前置阅读：`docs/功能案-工具集壳.md`（分页与注册表约定）

## 1. 要解决的问题

DSH 的「我的东西」散在 `$DSH_HOME` 下，但应用本身没有任何导出/导入入口：

- **换机器**：只能 `cp -R ~/.dsh`，把 1.7G 里 300M 的运行时和 26M 缓存一起搬走，
  搬完发现插件面板全 404（`node_modules` 里的包版本对不上）、密钥没了、会话列表空着；
- **插件搬运**：自己装的 7 个插件（其中一个 152M）散在 `profiles/desktop/node_modules/`，
  新机器上要照着 `package.json` 一个个重装，私有插件还得重新找源；
- **模型配置**：`cordis.patch.yml` 里 31 个模型条目、5 个 provider、各自的 baseURL 与 API key，
  重配一遍至少半小时，还容易抄错 `contextWindow` / `maxTokens`；
- **会话**：556 个会话、558M，删了不可重建，但没有任何导出手段；
- **改坏了没法回滚**：改一次 profile 之前没有留底，改错只能凭记忆重来。

实测规模（写本功能案时这台机器的真实数字）：

| 目录 | 大小 | 备份价值 |
| --- | --- | --- |
| `sessions/` | 558M（556 个会话） | **高**：聊天记录不可重建 |
| `attachments/` | 436M | 中：会话引用的图片，丢了图就断 |
| `profiles/` | 505M | **高**：其中 `node_modules/` 503M 是插件本体；`cordis.patch.yml` 只有 40K |
| `dsh-toolkit/` | 488M | 中：绝大部分是生成图片，配置只有几百 KB |
| `storages/` | 415M | 低：多为可重建缓存；`workspace.json`、`schedule.json` 值得留 |
| `skills/` | 52K | 高：自己写的技能 |
| `.credentials.yaml` | 1.2K | **高**：所有 API key |
| `dsh-runtimes/` `cache/` | 311M + 26M | 无：可重建 |

**本功能**：在 toolkit 里加「备份」分页，勾选要带走的东西导出一个 `.tar.gz`，
在另一台机器导入后即可正常工作（工作区路径相同时会话直接可用）；
导入前自动留快照，随时回滚。

## 2. 目标与非目标

### 目标

| 编号 | 目标 |
| --- | --- |
| G1 | **插件可搬运**：把已装插件（含本体与传递依赖）连同 `package.json`、`pnpm-lock.yaml` 一起带走，新机器导入后插件直接可用 |
| G2 | **模型与 API 配置可搬运**：`cordis.patch.yml` 原样带走（含 provider、baseURL、模型条目、`reasoningEfforts`） |
| G3 | **密钥可搬运且不裸奔**：`.credentials.yaml` 与配置里的明文 key 放进**口令加密**的独立块，没有口令解不开 |
| G4 | **会话可搬运**：整体导出或按工作区筛选；工作区路径相同时，导入后直接出现在列表里 |
| G5 | **跨机器可用**：导入后给出「要重启 / 要补什么」的明确清单，而不是让用户自己猜 |
| G6 | **可回滚**：写盘前把将被覆盖的文件快照到插件目录，一键还原 |
| G7 | **不糊里糊涂产出 1.2G 文件**：导出前显示每类体积，给三个预设按钮 |

### 非目标

- **不做云同步、不做定时自动备份。** 只有点按钮才产出文件。
- **不做增量 / 去重 / 归档轮转。** 每次都是完整快照（可选 gzip）。
- **不解析会话日志。** `session.v4.jsonl.zstd` 是 zstd 压缩的私有追加日志，Node 无内置 zstd、
  插件不引依赖，所以**按字节复制**（这也是它能跨机器用的原因：原样交还给 DSH）。
- **不备份可重建的东西**：`dsh-runtimes/`、`cache/`、`storages/session_projcache*`、
  `node_modules/.bin`。
- **不自动改写路径。** 工作区路径不同时，只提供「重映射」选项与提示，不擅自改用户数据目录名。
- **不主动触发 Loader 重载。** 导入只写文件，提示重启 App（热改 profile 会炸组合树，见 `功能案-工具集壳.md`）。

## 3. 关键约束

| 编号 | 约束 | 依据 | 本功能怎么办 |
| --- | --- | --- | --- |
| C1 | 会话是私有二进制格式 | `sessions/<工作区编码>/<sessionId>/session.v4.jsonl.zstd` | 只做文件级复制；manifest 记 `format: 'session-log-v4'` 与 DSH 版本，跨大版本给警告 |
| C2 | 会话目录名由工作区路径编码而来 | 实测 `/Users/x/proj` → `--Users-x-proj--` | manifest 记 `workspaces: [{path, dir}]`；导入时路径相同则直接落位，不同则提示重映射 |
| C3 | 插件是 `node_modules` 里的实体，不是清单 | `profiles/desktop/node_modules` 164 个目录 / 503M，其中用户插件 197M | 从 `package.json.dependencies` 出发**递归解析传递依赖**，只打包用户插件闭包；核心 `@deepseek-ai/*` 不打包（DSH 自带） |
| C4 | `link:` 依赖是绝对路径 | `"dsh-toolkit": "link:/Users/x/project/…/dsh-toolkit"` | 记进 manifest 的 `links`，导入时保留原值并提示「这一项要重新 link」；不自动改写 |
| C5 | 凭据是明文 YAML | `.credentials.yaml` 权限 0600、明文 | 放进口令加密块（AES-256-GCM + scrypt），没有口令无法解开；不勾就不带 |
| C6 | 配置里的 key 也是明文 | `cordis.patch.yml` 里 `anysearchApiKey` 等 | 普通块里的配置默认打码 `<redacted>`；原文放进加密块，导入时用解密后的整份文件替换 |
| C7 | 热改 profile 会触发重载并可能打挂组合树 | 见 `功能案-工具集壳.md` 的「不许追加注释触发重载」 | 只写文件，不 reload、不追加注释；面板写「重启后生效」 |
| C8 | 正在跑的会话被 `session.lock` 占着 | 每个会话目录里有 `session.lock` | 导入时跳过 live 会话（`ctx.sessions.get(id)` 命中即跳过）；导出时允许但 manifest 标 `live: true`（可能缺尾） |
| C9 | Node 无内置 tar / zstd；插件不引依赖 | `dependencies` 为空 | tar 自己写（512 字节头 + 1024 字节结束块），gzip 用 `node:zlib`，加密用 `node:crypto` |
| C10 | 备份文件可能被拷到别处 | 用户会丢进网盘 / U 盘 | 解包逐条目校验：相对路径、无 `..`、无符号链接、解析后必须在类别根内（防 tar-slip） |
| C11 | 数据量大 | 全量约 1.7G | 默认「迁移」预设约 760M；导出流式写盘，不整份进内存；单包上限 4 GiB |
| C12 | 导入是破坏性操作 | 覆盖 `cordis.patch.yml` 会改整个运行环境 | 写前快照到 `backup/before-<ts>/`，可一键回滚 |

## 4. 数据模型与落点

产物：`<YYYYMMDD-HHmmss>[-tag].tar.gz`，解开后：

```

  profile/
    cordis.patch.yml         # 打码版（含 API key 的字段替换为 <redacted>）
    cordis.yml
    package.json             # 保留 link: 原值
    pnpm-lock.yaml
  plugins/
    node_modules/
      dsh-free-search/…
      @michengai/dsh-cost-meter/…
      …                      # 用户插件的传递依赖闭包
  settings/
    settings.json
  skills/
    <name>/SKILL.md …
  agents/
    AGENTS.md
  sessions/
    --Users-x-project-demo--/<sessionId>/session.v4.jsonl.zstd
  toolkit/
    …                        # 插件数据（图片 / 剪贴板内容为子选项）
  storages/
    workspace.json

  secrets/
```

### 4.2 可导出的类别（白名单）

九个 id，面板上就是九个勾选框：

| id | 名称 | 来源 | 默认 | 体积 | 含敏感 |
| --- | --- | --- | --- | --- | --- |
| `profile` | 模型与插件配置 | `profiles/<p>/cordis.patch.yml`、`cordis.yml`、`package.json` | ✅ | 40K | 有明文 key（默认打码） |
| `plugins` | 插件本体 | 从 `package.json.dependencies` 递归出的插件闭包 | ✅ | ~197M | 无 |
| `settings` | 设置 | `ctx.settings.describe()` 序列化 | ✅ | <10K | 可能有 |
| `skills` | 技能 | `skills/` | ✅ | 52K | 无 |
| `agents` | 全局指令 | `AGENTS.md` | ✅ | 4K | 无 |
| `toolkit` | 插件数据 | `dsh-toolkit/`，子选项「含生成图片」「含剪贴板」 | ✅（都不含） | 620K / 488M | 剪贴板可能含日志正文 |
| `sessions` | 会话 | `sessions/`，可按工作区筛选 | ✅ | 558M | **有**：聊天正文、工作区路径 |
| `storages` | 工作区注册表 / 定时任务 | `workspace.json`、`schedule.json` | ✅ | 40K | 有路径 |
| `secrets` | 密钥（加密） | `.credentials.yaml` + 配置里的明文 key | ❌ | 2K | **有**：需要口令 |

**永不导出**：`node_modules/.bin`、`@deepseek-ai/*` 核心包、`dsh-runtimes/`、`cache/`、
`storages/session_projcache*`、`.DS_Store`。

### 4.3 三个预设

| 预设 | 勾选 | 体积 | 场景 |
| --- | --- | --- | --- |
| 轻量配置 | `profile` `settings` `skills` `agents` `toolkit` | ~800K | 只带走「我的偏好与配置」，插件重装 |
| **迁移到新机器**（默认） | 上面 + `plugins` `sessions` `storages` | ~760M | 换电脑，导入即用 |
| 完整备份 | 全部（含 `secrets`，需输入口令） | ~1.2G | 留底，含密钥 |

勾 `secrets` 时必须输入口令（≥8 位），否则导出按钮禁用——没有口令的加密块等于没有。

### 4.5 本地落点

```
~/.dsh-backups/                        # 默认导出目录（BACKUP_DIR 可覆盖）
  20261022-170500-travel.tar.gz
  before-1760000001000/                # 导入前快照（原样字节）
    manifest.json
    profile/cordis.patch.yml
```

插件自己的记录文件仍在 `$DSH_HOME/dsh-toolkit/backup/index.json`（与用户指定目录分离，
用户可以随手清空导出目录而不影响插件状态）：

```json
{
  "version": 1,
  "items": [
    { "id": "20261022-170500-travel", "kind": "export", "path": "/Users/x/.dsh-backups/20261022-170500-travel.tar.gz", "bytes": 320000000, "targets": ["profile", "plugins", "sessions"], "at": 1760000000000 },
    { "id": "before-1760000001000", "kind": "before", "path": "…/dsh-toolkit/backup/before-1760000001000", "targets": ["profile"], "at": 1760000001000 }
  ],
  "lastImport": { "archive": "…", "at": 1760000001000, "before": "before-1760000001000" }
}
```

环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `BACKUP_DIR` | `~/.dsh-backups` | 默认导出目录（必须绝对路径；不允许落在 `$DSH_HOME` 内，避免递归自备份） |
| `BACKUP_INDEX` | `$DSH_HOME/dsh-toolkit/backup/index.json` | 记录文件 |
| `BACKUP_MAX_BYTES` | `4294967296`（4 GiB） | 单包硬上限 |

### 4.6 密钥加密块

`secrets/secrets.json.enc` = `salt(16) || iv(12) || tag(16) || ciphertext`：

```
明文 JSON：{
  "credentialsFile": "<.credentials.yaml 原文>",
  "profileFiles": { "cordis.patch.yml": "<原文>", "package.json": "<原文>" },
  "exportedAt": 1760000000000
}
算法：scrypt(passphrase, salt, 32) → AES-256-GCM(iv)
```

- 只在勾 `secrets` 时生成；口令不落盘、不进日志，只在一次请求的生命周期里存在。
- 导入时口令错 → `backup/bad-passphrase`（422），不解密也不覆盖任何文件。
- 解密成功后：`credentialsFile` 写到 `$DSH_HOME/.credentials.yaml`（0600），
  `profileFiles` 覆盖打码版配置（这样导入后的配置**带着可用的 key**）。
- `secrets.txt` 里只有 ref 列表（「本备份包含 5 个密钥：天天中转站、anysearch…」），没有任何值。

## 5. 接口契约

前缀 `/api/backup`。

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `/api/backup/summary` | — | `{ ok, defaultDir, profile, targets: [{id, name, available, files, bytes, sensitive, hint}], presets: [{id, name, targets, bytes}], credentials: [{ref, label, configured}] }` |
| POST | `/api/backup/export` | `{ targets[], preset?, destDir?, tag?, sessions?: {workspaces?, since?}, includeImages?, includeClipboard?, passphrase? }` | `{ ok, backup: { id, path, bytes, files, manifest } }` |
| POST | `/api/backup/inspect` | `{ archive, passphrase? }` | `{ ok, manifest, conflicts: [{path, exists, bytes}], workspaces: [{path, dir, exists}], links: [] }` |
| POST | `/api/backup/import` | `{ archive, targets[], mode: 'skip' \| 'replace', passphrase?, remap?: [{from, to}] }` | `{ ok, before, written, skipped, needsRestart: true, missing: { links: [], secrets: [] } }` |
| POST | `/api/backup/restore` | `{ id }` | `{ ok, restored, needsRestart: true }` |
| GET | `/api/backup/list` | `?limit=50` | `{ ok, items: [{id, kind, path, bytes, targets, at, exists}] }` |
| POST | `/api/backup/delete` | `{ id, deleteFile? }` | `{ ok, removed }` |

错误码：

| code | 状态 | 场景 |
| --- | --- | --- |
| `backup/invalid` | 400 | targets 为空 / 未知、destDir 非绝对路径、destDir 在 `$DSH_HOME` 内、tag 含非法字符 |
| `backup/not-found` | 404 | 备份 id / archive 不存在 |
| `backup/too-large` | 413 | 预估超 `BACKUP_MAX_BYTES` |
| `backup/bad-archive` | 422 | 非法 tar.gz、manifest 缺失、sha256 不符、条目越界 |
| `backup/bad-passphrase` | 422 | 口令错 / 加密块损坏 |
| `backup/busy` | 409 | 已有导出 / 导入在跑 |
| `backup/unavailable` | 503 | 目录不可写 / 磁盘不足 |

## 7. 安全与隐私

1. **密钥必须加密。** `secrets` 类别只能以口令加密块形式存在（AES-256-GCM + scrypt，
   salt 16 / iv 12 / tag 16）；没勾 `secrets` 时包里**一个 key 都没有**，只有 ref 名。
2. **普通块里配置默认打码。** `apiKey` / `api_key` / `token` / `secret` / `password`
   （大小写不敏感）的值 → `<redacted>`。要原件只能勾 `secrets` 并给口令。
3. **口令不落盘**：不写日志、不进 `index.json`、不留在内存超过一次请求；错误口令不透露原因。
4. **tar-slip 防护**：解包逐条目校验相对路径、无 `..`、无符号链接条目（typeflag `2`）、
   解析后的绝对路径必须在类别根内；任一不合规整包拒绝。
5. **完整性**：每条目导入前比对 sha256；不匹配整包拒绝，不留半截状态（先全部暂存到
   `backup/staging-<ts>/`，校验通过再移动到位）。
6. **导入前快照**：`mode: 'replace'` 时被覆盖文件先复制到 `backup/before-<ts>/`，可回滚。
7. **目录边界**：`destDir` 必须是绝对路径且**不能**在 `$DSH_HOME` 内（防止备份文件被下一次
   备份再打包，指数膨胀）；插件目录写入只发生在白名单类别根下。
8. **权限**：备份文件 `0600`、快照目录 `0700`、`.credentials.yaml` 导入后 `0600`。
9. **不联网**：没有任何上传通道。
10. **面板提示**：备份含聊天记录、工作区路径与（可选）密钥，按敏感文件保管；
    勾 `secrets` 时二次确认「这个文件包含可用的 API key，泄露等于账号被盗用」。

## 8. 验收标准

1. 语法与构建：

   ```bash
   node --check components/backup/host.js
   node --check components/backup/tar.js
   node --check components/backup/crypto.js
   node --check components/backup/client.js
   node build.mjs && node tools/check-client.mjs && node tools/scrub-check.mjs
   ```

2. 自检（`tools/check-client.mjs`）至少覆盖：

   **打包**
   - tar round-trip：3 个文件（中文名、空文件、1 MiB 随机字节）→ 打包 → 解包 → 逐字节一致、sha256 一致；
   - 长文件名（>100 字节）走 `prefix` 拆分的正确性；
   - tar-slip：含 `../evil.txt`、`/etc/passwd`、符号链接条目的包 → `backup/bad-archive`，树外无新文件；
   - `mode: 'skip'` 不覆盖已有文件、`skipped` 正确；`mode: 'replace'` 产生 `before-*` 且 `restore` 逐字节还原。

   **插件搬运**
   - 从假 `package.json` 递归解析依赖闭包：只含用户插件，不含 `@deepseek-ai/*` 核心包；
   - `link:` 依赖记进 `links`、不打实体、导入后 `missing.links` 里列出；
   - 导入后 `node_modules/<pkg>/package.json` 的 version 与 manifest 一致。

   **密钥**
   - 不勾 `secrets` → 包内 grep 不到 `.credentials.yaml`、grep 不到任何 key 值；
   - 勾 `secrets` 但口令 <8 位 → 400；口令错 → `backup/bad-passphrase` 且不覆盖任何文件；
   - 正确口令 → 解密后 `.credentials.yaml` 与原文一致、profile 里的 key 回填成功；
   - 加密块用不同 salt 两次导出，密文不同（证明不是固定 IV）。

   **脱敏与边界**
   - `cordis.patch.yml` 里 `apiKey: <fixture>` → 普通块里是 `<redacted>`；
   - `targets: ['nope']` / `targets: []` → 400；
   - `destDir: 'relative/path'`、`destDir: '$DSH_HOME/backups'`、含 `..` → 400；
   - `BACKUP_MAX_BYTES=1` → 413；
   - 会话 live 跳过；`workspaces` 筛选只含指定工作区；`remap` 能把旧目录名映射到新路径编码。

   **面板**
   - 分页标签含「备份」；九类勾选框齐全；三个预设按钮；合计随勾选变化；
   - 勾 `secrets` 才显示口令框；口令 <8 位时导出按钮 disabled；
   - 导入前先请求 `inspect`，冲突清单与工作区提示都渲染。

3. 手工验收（真实环境）：

   1. 「轻量配置」导出 → < 1 MB，解开有 `manifest.json`，无 `secrets/`；
   2. 「迁移到新机器」导出 → 约 760M，插件闭包 7 个、无 `@deepseek-ai/*`；
   3. 把包拷到另一台机器（或临时 `DSH_HOME` + 同路径工作区）导入 → 插件面板正常、
      模型列表 31 条都在、会话列表出现；
   4. 工作区路径不同时：不 remap → 会话目录落成原编码（列表里不显示）；
      remap 到新路径 → 列表里出现；
   5. `replace` 再导入一次 → `before-*` 产生，回滚后逐字节一致；
   6. 勾 `secrets` 导出 → 不输入口令无法解出密钥；口令正确才解密。

## 9. 已知限制

- **工作区路径不同时，会话不会自动出现。** 目录名是路径编码，导入后按原编码落位；
  要让它出现在列表里，要么在目标机器上把工作区放到同一路径，要么用 `remap`
  （改目录名 + 改 `workspace.json` 里的路径）。`remap` 对 `session.v4.jsonl.zstd` 内部
  记录的 cwd **不生效**（那是压缩二进制里的字段），所以老会话的「工作目录」仍显示旧路径。
- **插件跨版本可能不兼容。** 插件包按字节搬，导入到 DSH 大版本不同的机器上可能加载失败
  （manifest 记了 `app.version`，不一致时红字警告，仍允许导入）。
- **`link:` 依赖需要手工处理。** 插件本体不打实体（它是你的源码仓库），导入后要重新 link。
- **会话导出时正在跑的会话可能截断。** 只读当时磁盘字节，manifest 标 `live: true`。
- **`attachments/` 不在类别里。** 不带的话，导入后老会话里的图片 / 附件会显示不出来。
  后续可作为 `sessions` 的子选项，本版先不做（体积 +436M）。
- **不做增量。** 两次导出大量重复字节。
- **单包上限 4 GiB**（`BACKUP_MAX_BYTES`），全量（含图片与附件）会超，需分次导出。
- **不支持命令行导入**，只能通过面板。
- **macOS 上首次写入 `~/.dsh-backups` 可能要授权目录访问**（系统会弹一次）。
