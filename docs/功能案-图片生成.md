# 功能案：图片生成（components/image-gen）

> 状态：已实现
> 关联组件：`components/image-gen/`（host.js + client.js + README.md）
> 同步维护：本文与 `components/image-gen/README.md` 保持一致，改动时请同时更新。
> 面板位置：侧边栏「工具集」（order 48）→ 分页「图片生成」；面板 key `image-gen`。合并前它是独立的侧边栏入口（order 49），`ctx.layout.selectPanel('image-gen')` 仍可直接打开。

## 1. 要解决的问题

1. **DSH 本身没有生图能力。** Agent 需要在被要求「生成 / 绘制 / 编辑图片」时直接调到一个工具，
   而不是让用户复制提示词去别处手搓。
2. **生图网关的接口五花八门。** 各家厂商、中转站、自建服务都有自己的协议。只按**标准 OpenAI Images 接口**
   （`POST {baseURL}/images/generations`）实现一条通路，就能覆盖绝大多数网关，同时不把插件绑死在某个服务商上。
3. **一个密钥不够用。** 用户可能同时接多个网关（官方、中转、本地），每个网关有自己的地址和密钥。
   需要「一个网关一组」的组织方式，而不是全局共用一个 `CUSTOM_API_KEY`。
4. **图片 URL 会过期。** OpenAI Images 返回的 URL 约 24 小时有效，聊完就失效。必须当场落盘，
   并把本地路径与 URL 一起返回。
5. **生成用的提示词会丢。** 提示词只存在对话里，回头想复现某张图只能翻聊天记录。需要把「图 → 提示词」
   记成索引，在图旁边直接展示。
6. **收藏很容易变成第二份图库。** 一旦「收藏」复制文件，就会有两份目录、两套删除语义。
   收藏应当只是原目录上的一个标记。
7. **参考图会被原样发给第三方。** 本地路径不能放行任意文件（密钥文件、JSON、超大的视频都被塞进请求体）。

## 2. 目标与非目标

### 目标

- 注册 `generate_image` 工具，走标准 OpenAI Images 接口：`POST {baseURL}/images/generations`，
  请求体为

  ```json
  { "model": "<模型 id>", "prompt": "<提示词>", "n": 1, "size": "1024x1024" }
  ```

  图生图时追加 `"image": [<https URL / data URL>…]`。**不走 chat/completions，也没有厂商私有协议。**
- **不内置任何厂商模型**：模型目录完全由用户添加，插件本身不绑定任何服务商。
- 文生图：`prompt` 必填 + `size`（像素尺寸，默认 `1024x1024`）+ `count`（1-4）。
- 图生图 / 编辑：`image` 数组（本地路径、https URL 或 data URL，≤9 张），prompt 里描述改动要求。
- 返回图片 URL（约 24 小时有效）+ 落盘本地路径（默认 `$DSH_HOME/dsh-toolkit/image-gen/images/`）。
- 目录为空、或默认模型没有可用密钥时**快速失败**并给出可操作提示，不触网。
- 面板「图片生成」：左列收纳（最近生成 / 收藏库 / 提示词库）· 右列文生图 / 图生图 / 设置。
- 图片旁注提示词、提示词库、收藏索引，以及两个历史数据回填脚本。

### 非目标

- 不实现任何厂商私有生图协议，也不做 chat/completions 兼容层。
- 不内置模型、默认地址或网关；没有「开箱即用」的模型列表。
- 不做图片编辑器（裁剪、涂抹、局部重绘参数面板）；图生图只把参考图原样转发，改动全靠 prompt。
- 不复制图片来做收藏、不维护第二份图库。
- 不做自动迁移：不搬老位置，也不写 `.migrated` 之类的标记。
- 面板「测试」只做 `/models` 可达性检查，不触发扣费生成。

## 3. 关键约束（决定了方案形状）

| # | 约束 | 依据 | 后果 |
|---|---|---|---|
| C1 | 只对接标准 OpenAI Images 接口 | README：统一走 `POST {baseURL}/images/generations`，不走 chat/completions、无厂商私有协议 | 只有一种请求体形状；`size` 只取 5 个 OpenAI 标准值；网关兼容性由用户自担 |
| C2 | 插件不内置厂商模型、不绑定服务商 | README 设计原则：模型目录完全由用户添加 | 目录为空时必须快速失败并给可操作提示（指向「设置」），不能静默调不通 |
| C3 | 图片 URL 约 24 小时过期 | README：返回 URL + 落盘本地路径 | 每张图必须落盘到 `imageDir()`；下载失败返回 null，但 URL 仍然返回 |
| C4 | 一个网关一组，密钥按组隔离 | README：组名 + 链接 + 该组自己的密钥；组间互不覆盖 | 每组建 `keyEnv = IMAGE_GEN_KEY_<组 id>`，不再有共用的自定义模型密钥变量 |

| C7 | 参考图会原样进入请求体发给第三方 | README：参考图校验（本地路径）一节 | 本地路径必须过扩展名白名单 + 文件头嗅探 + 10 MB 上限；https/data URL 走各自分支 |
| C8 | 旁注与计费记录是「锦上添花」，不能拖垮生成 | README：写失败静默，绝不影响生成结果 | `prompts.js` / `usage.js` 的写入失败一律吞掉；读取失败降级为空索引 |
| C9 | 数据落点统一在 `$DSH_HOME/dsh-toolkit/`，且没有自动迁移 | README「没有自动迁移」+ 根 README 的 `mv` 命令 | 所有路径经 `paths.js` 解析；升级靠用户手工搬，面板「设置」页可核对落点 |
| C10 | 配置文件里同时有模型目录与明文密钥 | README：`keys` 仅凭据库不可写时才落这里 | 配置文件写 0600；密钥解析优先凭据库，明文字段只作回落 |

## 4. 数据模型与数据落点

### 4.1 数据目录与环境变量

模型目录统一在面板「设置」Tab 管理，落盘到本机配置文件（权限 0600）。`$DSH_HOME` 先读环境变量
`DSH_HOME`（空白字符串视为未设，值支持 `~` 展开），未设则回退 `~/.dsh`，本机默认数据目录即
`~/.dsh/dsh-toolkit/`：

| 用途 | 环境变量 | 默认路径 |
| --- | --- | --- |
| 数据目录 | `DSH_TOOLKIT_DATA` | `$DSH_HOME/dsh-toolkit` |
| 生成图目录 | `IMAGE_GEN_DIR` | `$DSH_HOME/dsh-toolkit/image-gen/images` |
| 模型目录 | `IMAGE_GEN_CONFIG` | `$DSH_HOME/dsh-toolkit/image-gen/config.json` |
| 提示词库 | `IMAGE_GEN_LIBRARY` | `$DSH_HOME/dsh-toolkit/image-gen/library.json` |
| 花费记录 | `IMAGE_GEN_USAGE` | `$DSH_HOME/dsh-toolkit/image-gen/usage.jsonl` |
| 提示词索引 | `IMAGE_GEN_PROMPTS` | `$DSH_HOME/dsh-toolkit/image-gen/image-prompts.json` |
| 收藏索引 | `IMAGE_GEN_FAVORITES` | `$DSH_HOME/dsh-toolkit/image-gen/favorites.json` |

路径解析集中在 `paths.js`（按调用时的环境变量解析，不缓存），`cleanText` 也在这里，全组件共用。

### 4.2 模型目录 `config.json`（v2）

目录按「**组**（一个网关一条）+ 组内模型」组织：

```jsonc
{
  "version": 2,
  "providers": [
    { "id": "p…", "name": "组名（缺省取域名）", "baseURL": "https://…/v1", "keyEnv": "IMAGE_GEN_KEY_P…" }
  ],
  "models": [
    { "id": "<组 id>:<上游模型名>", "providerId": "p…", "name": "显示名", "model": "上游模型名", "pricePerImage": 0.04 }
  ],
  "defaultId": "<models[].id>",
  "keys": { "<keyEnv>": "明文密钥（凭据库不可写时才落这里）" }
}
```

- 模型 id 由「组 id + 上游模型名」推导，所以同一个模型挂到两个组不会撞车。
- **配置结构迁移（v1 → v2，懒迁移）**：读到老结构（平铺 `models[]` 带 `group` / `baseURL` / `keyEnv`，
  没有 `version` / `providers`）即按 `(baseURL, keyEnv)` 归成组——组名取域名、组 id 用 `p1` / `p2`…
  （确定性，重复读取 id 不变）——`defaultId` 从旧 id 映射到新 id，`keys` 原样保留（老用户已存的密钥不丢）；
  首次写入才落盘，用户不需要做任何事。
- 密钥解析顺序：配置文件 `keys[keyEnv]` → DSH 凭据库 → 环境变量 `$keyEnv`；`keyEnv` 由所属组决定，
  面板新建的组用 `IMAGE_GEN_KEY_<组 id>`（组间互不覆盖），不再有一个共用的自定义模型密钥变量。
  保存时优先写凭据库，凭据服务不可写才回落配置文件；`CUSTOM_API_KEY` 只在旧配置迁移过来、或手工指定时
  作为某个组的 `keyEnv` 出现。

### 4.3 图片文件

- 目录：`imageDir()`，默认 `$DSH_HOME/dsh-toolkit/image-gen/images/`，`IMAGE_GEN_DIR` 可覆盖；
  与 `favorites/` 等历史目录不并存——**读取端只扫这一个目录**（`scanImageDirs()` 返回 `[imageDir()]`）。
- 文件名：`image-gen-<UTC 时间戳>-<序号>.png`，即 `saveImage` 里的
  `${FILE_PREFIX}-${stamp}-${index + 1}.png`（`FILE_PREFIX = 'image-gen'`，`stamp` 是 ISO 时间去掉
  `-`、`:` 与毫秒）。
- 落盘策略：文生图与图生图统一走 `generateMany` → 每张成功后 `saveImage`；返回的条目带 `{ name, url }`，
  面板与工具都从 `files` 拿本地绝对路径。下载失败时 `saveImage` 返回 `null`，URL 照旧返回。
- 所有按名字取文件的接口都先 `basename()` 再比对白名单
  `/^[A-Za-z0-9._-]+\.(png|jpe?g|webp|gif)$/i`，用于阻断目录穿越。

### 4.4 图片 → 提示词索引（图片旁注）

生成的图片旁边直接标注生成它时用的提示词，不用回头翻对话记录。

- 索引文件：`IMAGE_GEN_PROMPTS` → `$DSH_HOME/dsh-toolkit/image-gen/image-prompts.json`
- 结构：`{ version: 1, images: { "<图片名>": { prompt, model, size, mode, createdAt } } }`，权限 0600
- 记录时机：`generateMany` 每张成功落盘后，一次生成的多张**统一写一遍**
  （原子写 = 临时文件 + rename；写失败静默，绝不影响生成结果）
- `mode`：`text`（文生图）/ `image`（图生图，带参考图）
- **老图回退**：索引里没有的图片，按 `library.json` 的 `prompts[].images` 反查，
  `promptSource` 标 `library`，面板注明「提示词（按提示词库反查）」；两边都没有则显示「无提示词记录」
- 展示：左栏图块下方两行截断（悬停全文）、灯箱右侧独立一栏（分段 + 可复制 + 模型/尺寸事实条）、
  生成结果卡片旁注；无记录的老图退化成弱化文件名
- 列表接口的 `files` 项直接带 `prompt` / `promptSource` / `promptTitle`，面板零额外请求
- 删除图片时同步清掉索引条目；`POST /api/image-gen/generate` 回传真正发给上游的 `prompt`
- 存量回填：`node tools/backfill-prompts.mjs [--write]` 把旧版 `$DSH_HOME/dsh-imagegen/index.json`
  里的提示词搬进新索引（幂等，新记录优先，对不上的不臆造）
- 会话回填：`node tools/backfill-from-session.mjs --session <session.v4.jsonl.zstd> [--usage usage.jsonl] [--write]`
  从会话日志里捞 `generate_image` 的调用参数，按「落盘时间在调用后 150 秒内 + 张数不超 count」配对回填
  （同样幂等、新记录优先；窗口内图多于 count 视为有并发任务，拒绝配对）。会话日志是**追加式多帧 zstd**，
  脚本内部逐帧解压；`--usage` 就近取模型名（间隔超 `--usage-window` 毫秒则不补）

### 4.5 提示词库 `library.json`

- 库文件：`IMAGE_GEN_LIBRARY` → `$DSH_HOME/dsh-toolkit/image-gen/library.json`
- 每条记录：`{ id, title, text, size, images: [图片名…], createdAt, updatedAt }`
- `images` 记录该条生成过的图片名，按名从统一目录回显；「加为风格」「替换主体」直接填入右栏表单

### 4.6 收藏索引 `favorites.json`

- `favorites.js`：`{ version: 1, images: { 文件名: { favoritedAt } } }`，0600
- 收藏 / 取消收藏只动 `favorites.json` 里的标记，图片始终只有 `image-gen/images/` 一份
- 删图时顺手清掉对应标记（`gallery-actions.js` 里的 `forgetFavorites`）
- 收藏库列表按 `favoritedAt` 倒序，只列文件仍存在的标记

### 4.7 生成计费记录 `usage.jsonl`

- `usage.js`：`IMAGE_GEN_USAGE` → 数据目录 `usage.jsonl`，每行 `{ time, model, size }`，
  追加写（mode 0600），失败静默
- 每成功生成一张记一条；成本不在写入时定格，由 token-usage 组件按「当前每张单价 × 张数」统一计算

### 4.8 每张单价与计费合并

- **每张单价**：**每条模型**自己的字段 `pricePerImage`（美元/张，模型编辑卡里填，不在组上）。
- 配了价的模型会出现在「Token 用量 → 计价明细」（按张展示），每次成功生成记一条到
  `$DSH_HOME/dsh-toolkit/image-gen/usage.jsonl`，由 token-usage 组件按「当前单价 × 张数」合并进成本统计
  （伪会话行「图片生成」）；没配价只记次数，成本记 0 并标「未配价」。

### 4.9 没有自动迁移

- 插件不做老位置搬迁，也不写 `.migrated` 标记。升级后按根 README「没有自动迁移」一节的 `mv` 命令手工整理即可；
  旧 `favorites/` 目录不必搬（里面的副本可以删掉，在面板里重新点一次收藏就会重新打标记）。
- 工具集 →「设置」分页能一眼核对每项的实际落点、是否存在、多大、什么时候改的。
- 插件目录的 `data/` 不再是运行时数据目录；`.gitignore` 仍然忽略它（历史遗留的空壳可以留着或删掉）。

## 5. 接口契约

所有路由前缀 `/api/image-gen/`。JSON 响应统一 `{ ok: true, ... }` 或 `{ ok: false, code?: 'image-gen/<reason>', message }`；
文件类路由 `GET …/file` 直接返回图片字节（而非 JSON）。

### 5.1 工具 `generate_image`

参数（原生 JSON-Schema，`additionalProperties: false`，`required: ['prompt']`）：

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `prompt` | string | ✅ | — | 详细的图片生成提示词，建议包含主体、风格、场景、构图、光线等细节；图生图时在这里描述改动要求 |
| `size` | string | | `1024x1024` | 输出像素尺寸：`1024x1024` / `1536x1024` / `1024x1536` / `1792x1024` / `1024x1792` |
| `count` | integer | | `1` | 生成张数，1-4 |
| `image` | string[] | | — | 参考图：本地图片文件路径、https URL 或 data URL，≤9 张；本地路径只接受 png/jpg/jpeg/webp/gif、文件头确为图片、单张 ≤10 MB |

工具超时 `timeoutMs = 360000`（6 分钟）。返回值（`additionalProperties: false`，`required: ['ok']`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `ok` | boolean | 是否成功 |
| `error` | string | 失败原因（失败时出现） |
| `model` | string | 实际使用的上游 model id |
| `count` | integer | 实际成功的张数（等于 `imageUrls.length`，不是请求值） |
| `size` | string | 实际尺寸 |
| `imageUrls` | string[] | 上游返回的图片 URL（去重后） |
| `imageUrl` | string | 首张 URL |
| `files` | string[] | 已落盘的本地绝对路径 |
| `partial` | string | 部分失败的说明 |

工具侧错误文案（原文，不返回错误码）：

- `prompt 不能为空`
- `模型目录为空：请先在「图片生成 → 设置」里添加一个模型（接口地址 + 模型 id）。`
- `默认模型「<显示名>」还没有密钥（<keyEnv>）：请在「图片生成 → 设置」里为该模型填入 API Key。`
- `参考图片最多 9 张`
- `参考图不是支持的图片格式（.txt）：…` 等可读原因
- `生图 API 返回空结果`；部分失败时为 `其中 N 张失败：…`

| Method | Path | 入参 | 返回字段 | 错误码 |
|---|---|---|---|---|

| POST | `/api/image-gen/config/models` | `{ id?, baseURL?, apiKey? }` | `{ ok, baseURL, models, all, added, message }` | 400（无 Key / 接口失败）、404 `没有这个模型组`、500 |
| POST | `/api/image-gen/generate` | `{ prompt, size?, count?, images? }` | `{ ok, model, size, count, prompt, files（文件名列表）, images[{ name, url? }], partial? }` | 400（prompt 空 / 目录空 / 无密钥 / 参考图错）、502（空结果）、500 |
| GET | `/api/image-gen/library` | — | `{ ok, library, path }` | 500 |
| POST | `/api/image-gen/library` | `{ action, … }` | `upsert` → `{ ok, id, entry, library }`；`delete` / `tag` → `{ ok, library }` | 400 `未知动作：…` / 校验失败、404 `记录不存在`、500 |

### 5.3 画廊与文件

- `GET /api/image-gen`：`offset` 默认 `0`，`limit` 默认 `24`、上限 `60`。`files[]` 每项形如
  `{ name, bytes, mtime, dir, prompt, promptSource, promptTitle, promptModel, promptSize, promptCreatedAt }`
  （旁注字段由 `attachImagePrompts` 在列表接口里直接返回，面板零额外请求；没有记录时 `prompt` / `promptSource`
  为 `null`、`promptTitle` 为空串）。列表按 `mtime` 倒序、同名再按名字排。
  `dirs` 只含统一图片目录；`saveDir` 供面板提示落点；`hasKey` / `baseURL` 用于顶部状态。
- `GET /api/image-gen/file?name=`：按扩展名给 `content-type`，`cache-control: private, max-age=3600`。
- `POST /api/image-gen/delete`：删文件，并 `forgetImagePrompts` + `forgetFavorites` 同步清索引。

### 5.4 收藏

- 列表按 `favoritedAt` 倒序，只列文件仍存在的标记；`starred` 为全量收藏名列表，`names` 为当前页名字。
- 收藏 / 取消收藏幂等：重复收藏刷新时间戳，取消不存在的标记返回 404。

### 5.5 模型目录

- `GET /api/image-gen/config` 返回完整 config（含 `keys`）。
- `POST /api/image-gen/config` 的 `action` 取值：
  `addProvider` / `updateProvider` / `removeProvider` / `addModels` / `updateModel` / `removeModel` / `setDefault`
  （`remove` 视为 `removeModel` 的别名）。成功时回带最新 `config`。
- `POST /api/image-gen/config/test`：`{ id }` 按目录里的模型测，`{ baseURL, apiKey }` 按表单里未保存的值测。
  只检查 `/models` 可达性，**不触发扣费生成**；返回 `status`（HTTP 码）、`count`（模型数）、
  `imageCount`（识别出的生图模型数）、`models`、`message`。401/403（Key 被拒）、404（无 `/models`）、
  非 200、非 JSON 都落成 `ok: false`。
- `POST /api/image-gen/config/models`：拉列表用。已保存的组可只传 `id`；表单里没保存的传
  `{ baseURL, apiKey }`；编辑已有组时 `apiKey` 留空自动用该组已存密钥，`baseURL` 以表单为准。
  返回 `models`（识别出的生图模型）、`all`（接口返回的全部模型）、`added`（其中未在该组里的）。

### 5.6 生成

- 入参：`{ prompt, size?, count?, images?: [{ kind: 'saved' | 'path' | 'url' | 'data', value }] }`。
  `kind` 决定参考图来源：`saved`（本组件图库里的文件名，按 `scanImageDirs()` 找，省掉导出再上传）、
  `path`（本机路径）、`url`（https）、`data`（data URL）。
- 返回 `prompt` 是**真正发给上游**的提示词（生成完再改表单也不会让旁注跟着串），旁注索引也用它。
- 返回的 `files` 是落盘后的**文件名**列表（面板按名字取图，不受 24 小时 URL 过期影响）；
  `images[]` 为 `{ name, url? }`，只回传 https URL，data URL 体积过大不回传。
- 400 的典型原因（文案原文）：`prompt 不能为空`；`模型目录为空：先在「设置」里添加模型（被删除的内置模型重新添加同 id 即可恢复）。`；
  无密钥时 `默认模型「<显示名>」还没有密钥（<keyEnv>）：打开「设置」为对应分组填入后再生成。`；
  参考图问题（`参考图片最多 9 张`、`参考图文件名非法`、`收纳里找不到这张图：<名>` 或校验失败原因）。
- 502：上游返回空结果，响应体为 `{ ok: false, message, model, size }`（无 `code`）。
- 部分失败：仍 200，额外带 `partial: '其中 N 张失败：<原因>'`。

### 5.7 提示词库

- `POST` 的 `action`：`upsert` / `delete` / `tag`。`tag` 的 `kind` 目前只接受 `prompt`（图片归档）；
  `upsert` 需要 `text`；`delete` 不存在时 404「记录不存在」；未知动作 400「未知动作：…」。

## 6. 面板与交互

### 6.1 位置与布局

- 侧边栏「工具集」（order 48）→ 分页「图片生成」。合并前是独立的侧边栏入口（order 49），
  面板 key 仍是 `image-gen`，`ctx.layout.selectPanel('image-gen')` 照样能直接打开。
- 左右两列：左列收纳，右列文生图 / 图生图 / 设置。

### 6.2 左列：收纳

- 最近生成 / 收藏库 / 提示词库三个标签、缩略图墙、收藏 / 删除 / 放大 / 下载。
- 每张图下面是**生成它用的提示词旁注**（两行截断，悬停看全文；灯箱右侧独立一栏显示完整文本，
  按空行分段，且灯箱只铺满面板本身，不盖左侧会话栏）。

### 6.3 右列：文生图

- 五段式提示词（主体 / 风格 / 构图与视角 / 光线与氛围 / 负面）+ 尺寸 / 张数。
- 尺寸与张数受工具契约约束：5 个标准尺寸、1-4 张。

### 6.4 右列：图生图

- 上传参考图、从左侧拖入缩略图、或填 URL / 本机路径，再写编辑指令。
- 参考图最终归一为 https URL / data URL 后才进请求体（本地路径分支按 §7 校验）。

### 6.5 右列：设置（模型组）

**一个网关一组**：组名 + 链接 + 该组自己的密钥。

- 顶部：默认模型下拉（按组分组）+「测试」+「刷新」，一行状态「N 个组 · M 个模型 · 密钥状态」
- 组卡片**可折叠**：组头一行是折叠箭头（▾ 展开 / ▸ 收起）+ 状态圆点 + 组名 + 链接 +「N 个模型」+
  右侧「编辑 / 删除」；折叠时只显示组头，展开后显示组内模型。默认只有 1 个组时展开、多个组时收起，
  手动开合在当前会话内记住
- 展开后组内：模型逐条一行（显示名 +「默认」/「$x.xx/张」标签 + 上游 model id，右侧「编辑 / 删除」），
  行下方一个虚线按钮「+ 添加模型」
- 「+ 添加模型组」与组头「编辑」/ 组内「+ 添加模型」打开的是**同一个组表单**：组名 / API Key / 链接
  （新建时三者都填，组名留空取域名、API Key 该组专用；编辑已有组时链接与组名预填，API Key 留空表示不改，
  占位符「留空不改」）
- 「获取模型」用**表单里当前的链接与 API Key** 拉该网关的模型列表（编辑已有组时 Key 留空自动用该组已存的
  那把，链接以表单里改过的为准，不必先保存），只列识别出的生图模型
- 勾选区：拉到的生图模型逐个可点选 / 取消（支持「全选 / 清空」），**已在该组里的模型置灰、不参与勾选**；
  网关不提供 `/models` 时可手填模型 id 后「加入」
- 底部按钮：「保存」（新建时可只建组不勾模型），编辑时左侧还有「删除组」（连组带模型一起删，有确认框）；
  保存语义：新建 = 建组 + 写入勾选的模型（目录为空时第一条自动成为默认），
  编辑 = 先把组名 / 链接 / 密钥的改动落盘，再把勾选的模型补进组（**只增不删**）

### 6.6 旁注与结果卡片

- 左栏图块下方两行截断（悬停全文）、灯箱右侧独立一栏（分段 + 可复制 + 模型/尺寸事实条）、
  生成结果卡片旁注；无记录的老图退化成弱化文件名。
- 老图按提示词库反查命中时注明「提示词（按提示词库反查）」；两边都没有显示「无提示词记录」。

## 7. 安全与隐私

1. **参考图不放行任意文件。** 本地路径分支：扩展名白名单 `png` / `jpg` / `jpeg` / `webp` / `gif`；
   文件头嗅探（扩展名对但内容不是图片——`.png` 里装着 JSON、密钥文件——一律拒绝）；
   单张上限 10 MB（`MAX_REFERENCE_BYTES`），超限拒绝；MIME 以**文件头**为准，不看扩展名
   （`.png` 里的 webp 按 `image/webp` 发）。拒绝时返回可读原因（如「参考图不是支持的图片格式（.txt）：…」），
   不静默降级。
2. **参考图会原样发给第三方。** `https://` URL 与 data URL 走各自分支，本地校验不适用、语义不变；
   面板与工具描述都明确提示「不要传敏感文件」。
3. **密钥分级存储。** 解析顺序 `keys[keyEnv]` → DSH 凭据库 → 环境变量；保存优先写凭据库，
   不可写才回落配置文件。`keys` 里只有凭据库不可写时才会出现明文。
4. **配置文件权限 0600。** config.json / library.json / image-prompts.json / favorites.json 均按 0600 落盘；
   索引采用临时文件 + rename 的原子写。
5. **目录穿越防护。** 所有按名字取文件的接口先 `basename()` 再比对白名单，任何带 `/`、`..` 的名字直接 400；
   读图目录固定为 `imageDir()`，没有「读任意路径」的路由。
6. **图片不落进项目目录。** 统一落在数据目录（`$DSH_HOME/dsh-toolkit/image-gen/images/`），与当前会话工作区无关。
7. **不偷偷花钱。** 设置里的「测试」只做 `/models` 可达性检查，不触发扣费生成。

## 8. 验收标准

1. `node --check components/image-gen/host.js`、`node --check components/image-gen/client.js` 通过。
2. 面板出现在「工具集」的分页里，标签「图片生成」，`order` 49，可被 `ctx.layout.selectPanel('image-gen')` 直达。
3. 模型目录为空时调 `generate_image`：立即返回「模型目录为空：…」，**不触网**。
4. 配置里给默认模型配了组、但该组没有密钥时：返回「默认模型「…」还没有密钥（…）：…」，不触网。
5. 文生图正常路径：返回 `ok: true` + `imageUrls` + `files`；`files` 指向的图片能在
   `GET /api/image-gen` 的 `files[]` 里看到，并带 `prompt` / `promptSource`。
6. 图生图：传本机合法 png 成功；传 `.txt`、伪造的 `.png`（内容非图片）、>10 MB 文件时被拒绝，
   返回可读原因；参考图超过 9 张返回「参考图片最多 9 张」。
7. 收藏 / 取消收藏后 `GET /api/image-gen/favorites` 的名列表与 `favoritedAt` 变化正确；
   删除一张已收藏的图后，收藏列表不再出现它，且磁盘上没有第二份图片副本。
8. 带 `/`、`..` 或非白名单扩展名的 `name` 请求 `GET /api/image-gen/file` 返回
   `{ ok: false, code: 'image-gen/bad-name', message: '非法文件名' }`（400）。
9. 回填脚本可用：
   - `node tools/backfill-prompts.mjs`（只读预览）/ `node tools/backfill-prompts.mjs --write`（落盘）
   - `node tools/backfill-from-session.mjs --session <session.v4.jsonl.zstd> [--usage usage.jsonl] [--write]`
   两者幂等、可重复执行，不覆盖已有新记录。
10. 根目录 `node build.mjs` + `node tools/check-client.mjs` 全绿（由维护者在合并前执行；本次只改文档，
    不要求重跑）。

## 9. 已知限制

- **没有任何自动迁移。** 老位置（`$DSH_HOME/dsh-toolkit/images/`、`config.json`、`library.json`、
  `usage.jsonl`、`image-prompts.json`、`favorites/`）需要按根 README 的 `mv` 命令手工搬；旧 `favorites/`
  目录不必搬，重新点一次收藏即可。
- **只支持标准 OpenAI Images 接口。** 私有协议、chat/completions 风格的「对话生图」、需要额外签名的网关
  都不在支持范围内。
- **没有内置模型。** 全新安装时目录为空，必须先添加组与模型；被删除的内置模型（历史遗留配置场景）
  重新添加同 id 即可恢复。
- **提示词索引是尽力而为。** 写入失败静默；老图只有命中提示词库才能反查，两边都没有时显示「无提示词记录」。
- **回填只覆盖两类来源。** 存量索引（旧 `index.json`）与会话日志里的 `generate_image` 调用参数；
  会话回填依赖「落盘时间在调用后 150 秒内 + 张数不超 count」的启发式配对，窗口内有并发任务时拒绝配对。
- **图片读取只认一个目录。** `scanImageDirs()` 返回 `[imageDir()]`，不做历史路径兼容。
- **未配价即成本 0。** 只有填了 `pricePerImage` 的模型才计入「Token 用量」的成本，其余只记次数并标「未配价」。
- **参考图的 https / data URL 分支不做本地校验。** 这两类由用户自行保证内容安全，插件只负责转发。
