# 功能案：剪贴板长文本转文件（components/clipboard）

> 状态：已实现（入口 `live-entry-68.js`）
> 关联组件：`components/clipboard/`（新建）、`components/toolkit/`（壳内置分页）
> 面板位置：toolkit 分页「剪贴板」（order 50，手动兜底按钮在该分页内）；toolkit 设置分页的「剪贴板」卡片只显示数据落点

## 1. 要解决的问题

从终端、CI、浏览器、编辑器里复制一大段内容粘进 DSH 输入框后：

- composer 被瞬间撑满，输入框高度吃掉半个屏幕，想改一句话得滚很久；
- 发送时这些内容全部变成 prompt token，既贵又容易超出上下文；
- 模型真正需要的往往只是「这个文件」，而不是「这坨文本」。

DSH 本身没有「长文本自动转文件」。现在只能手工做三步：先存文件，再在输入框里敲 `@` 选文件，或者干脆把文件扔进工作区。

**本功能要做的事**：粘贴发生的那一刻判断「这段够长」，把它原样落成一个文件，输入框里只插入一行 `@"路径"` 引用。

**不猜内容类型**：日志、JSON、SQL、堆栈、随便一堆字，都不做格式识别。扩展名只看剪贴板里带了什么文本格式——只带一种就按它（`text/html` → `.html`、`text/csv` → `.csv`、`text/plain` → `.txt`），同时带多种就统一存 `.txt`。

## 2. 目标与非目标

### 目标

| 编号 | 目标 |
|---|---|
| G1 | 一次粘贴完成「检测 → 落盘 → 插入 `@` 引用」，用户不需要额外动作 |
| G2 | 文件落在插件数据目录，按日期分文件夹、独立文件名、同内容自动复用 |
| G3 | 建索引并提供面板：查看、复制路径、预览、删除、一键「用 @ 引用」 |
| G4 | 触发阈值、开关、清理策略可配（toolkit 设置分页） |
| G5 | 任何一步失败都不丢内容：最差退回 DSH 原生粘贴 |

### 非目标

- 不做内容格式识别（不因为内容是 JSON 就命名 `.json`）、不做语法高亮、不做脱敏或摘要——内容逐字节原样保存；扩展名只跟随剪贴板提供的文本格式（见 4.2）。
- 不改 DSH 核心输入框、不注册 `conversation.composer` 替换，避免和它抢渲染。
- 不接管图片、文件粘贴（二进制），这些仍走 DSH 原生通道。
- 不做云同步、不自动上传；文件只在本机。
- 不自动注入到 prompt：只插入 `@` 引用文本，由用户决定发不发。

## 3. 关键约束

| 编号 | 约束 | 由此决定的做法 |
|---|---|---|
| C1 | DSH 没有把 composer 暴露成 Service（client Service 目录里没有 composer/commands，只有 `slots` / `layout` / `sessions` / `timer` 等） | 只能靠 DOM：在 `document` 上以 **capture 阶段**监听 `paste`，且仅当目标是编辑区（`textarea` 或 `[contenteditable]`）时介入 |
| C2 | 编辑区可能是受控组件 | 插入优先 `document.execCommand('insertText', false, text)`；失败退化为「原生 value setter + 派发 `input` 事件」；两者都失败则放弃插入、只保留文件与提示 |
| C3 | `@` 引用必须符合 DSH 的语法规则 | 依据 `@deepseek-ai/dsh-client-ui-reference` 的 `user-text-rules`：`/(?<!\S)(@"[^"\n]+"\|@[^\s]+)/u`。**含空白的路径必须写成 `@"路径"`**，无空白可写 `@路径`；路径后面接换行 |
| C4 | 落盘必须走插件数据根 | 写 `$DSH_HOME/dsh-toolkit/clipboard/…`，目录 `0700`、文件 `0600`；与 image-gen 一样由 host 侧直接 `fs` 写入，不经过 DSH 的 workspace 写策略 |
| C5 | 粘贴不能变卡 | 落盘超过 200ms 未完成就先放行原生粘贴（内容照常进输入框），落盘完成后提示「已另存为 X」，绝不吞掉用户内容 |
| C6 | 同一段内容常被反复粘贴 | 文件名带内容指纹：`<HHmmss>-<sha1 前 8 位>.<ext>`；同一天内同指纹 + 同扩展名直接复用，索引里 `hits + 1` |
| C7 | 超大文本会拖死编辑器 | 不做截断：正文完整写入文件，编辑器里只放 `@` 引用；面板列表只显示元数据 |
| C8 | 权限策略是 `workspace-write`，数据目录在 workspace 之外 | 写文件在 host 进程内完成（与 image-gen 落图片同一条路），不依赖会话写权限 |

## 4. 数据模型与落点

### 4.1 目录树与命名

```
$DSH_HOME/dsh-toolkit/
└── clipboard/
    ├── index.json                         # 索引（见 4.3）
    └── 2026-10-22/                        # 按本地日期分文件夹（0700）
        ├── 143012-a1b2c3d4.txt            # 只有纯文本
        ├── 120318-4b1e77c0.html           # 剪贴板只提供 HTML（内容为 HTML 源码）
        ├── 121002-a8d30f51.csv            # 剪贴板只提供 CSV
        └── 121530-55e0c712.txt            # 多份文本格式并存 → 统一 .txt
```

- 文件名：`<HHmmss>-<sha1(text) 前 8 位>.<ext>`。
- **扩展名规则**（细节见 4.2）：只带到一种文本格式时按它取扩展名；同时带多种时统一 `.txt`。永远不按内容猜（内容是 JSON 也不会叫 `.json`）。
- 为什么还要指纹：同一段内容重复粘贴时直接复用已有文件，面板里不会堆一堆同内容的副本。

### 4.2 触发条件

自动拦截需要**同时**满足：

1. 粘贴目标是 composer 编辑区；
2. 能取到文本：收集 `event.clipboardData.types` 里所有 `text/*` 副本（只有图片、文件等二进制时一个都没有，直接不介入），然后：
   - **只有一份** → 内容用它，扩展名按它的 mime：`text/plain` → `.txt`、`text/html` → `.html`、`text/csv` → `.csv`、`text/markdown` → `.md`、其它 `text/*` → `.txt`；
   - **两份及以上** → 扩展名统一 `.txt`，内容按 `text/plain` → `text/csv` → `text/html` → 其它 的顺序取第一份（即「有干净纯文本就用纯文本」）；
   - 取到哪一份都原样保存，不改一个字节；来源格式记进索引的 `mime` 字段。
3. 长度 ≥ `thresholdChars`（默认 **2000** 字符）**或** 行数 ≥ `thresholdLines`（默认 **30** 行）；
4. 自动模式开启（设置里可关）。

不满足就完全不介入，行为与现在一致。

手动兜底：分页面板顶部有「把当前剪贴板转成文件」按钮，读 `navigator.clipboard.readText()`
（点击手势，权限合法）后走同一套落盘 + 插入；编辑区定位不到时只复制引用、不插入。

### 4.3 索引 `clipboard/index.json`

```json
{
  "version": 1,
  "items": [
    {
      "name": "143012-a1b2c3d4.txt",
      "dir": "2026-10-22",
      "path": "/Users/x/.dsh/dsh-toolkit/clipboard/2026-10-22/143012-a1b2c3d4.txt",
      "bytes": 182344,
      "lines": 2048,
      "mime": "text/plain",
      "at": 1792650479000,
      "hits": 3
    }
  ]
}
```

- 只记录元数据，不存正文；`mime` 记录这一份的来源格式（`text/plain` / `text/csv` / `text/html` 等），与扩展名一起决定面板上的展示。
- `path` 存绝对路径（插入 composer 用的就是它）；接口另派生一个 `displayPath`（`$HOME` 换成 `~`）供面板展示。
- 文件被用户手工删掉时，读取列表阶段剔除并回写索引。
- 索引写盘沿用现有约定：`tmp` + `rename` 原子写、`0600`、失败静默。

### 4.4 环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `CLIPBOARD_DIR` | `$DSH_HOME/dsh-toolkit/clipboard` | 根目录 |
| `CLIPBOARD_INDEX` | `<根>/index.json` | 索引文件 |
| `CLIPBOARD_THRESHOLD_CHARS` | `2000` | 字符阈值 |
| `CLIPBOARD_THRESHOLD_LINES` | `30` | 行数阈值 |

`resolvePaths()` 里一并返回，toolkit 设置分页据此显示「被环境变量接管」。
清理参数（§4.5）只放在 `config.json` 里，不提供环境变量。

### 4.5 清理策略

默认**不清理**，但提供两条可选规则（`config.json` 里配置，面板「设置区」可改）：

| 字段 | 默认 | 含义 |
|---|---|---|
| `cleanupEnabled` | `false` | 自动清理总开关 |
| `cleanupMaxAgeDays` | `30` | 保留天数，按索引项 `at` 算；`0` = 不按天数清 |
| `cleanupMaxTotalBytes` | `0` | 总量上限（字节）；`0` = 不按总量清 |

触发时机：开关打开时，**粘贴落盘后**与**列表面板刷新时**各顺手清理一次；
面板「立即清理」按钮（`POST /api/clipboard/cleanup`）可随时手动触发，
请求里的 `maxAgeDays` / `maxTotalBytes` 只对这一次生效，不写回配置。

删除顺序与边界：

1. 先按天数：`now - at > maxAgeDays × 24h` 的条目进入删除列表；
2. 再按总量：剩余条目总量超过 `cleanupMaxTotalBytes` 时，从**最旧**开始删，降到上限以内立刻停；
3. 只处理路径落在 `<根>/<YYYY-MM-DD>/` 里的条目（目录名必须是 8 位日期）；
   索引里若出现指向别处的路径，一律计入 `skipped`、**不删文件**；
4. 单个文件删除失败只跳过它，不影响其余条目，也不抛出（清理是维护动作）；
5. 删空的日期目录顺手 `rmdir`（非空则忽略）；
6. 清理结果回 `{removed, freedBytes, names, skipped}`，面板据此提示。

不做「清空全部」：逐条删除已覆盖该需求，且一次性删光更容易误操作。

## 5. 接口契约

Host 侧六条路由（前缀 `/api/clipboard`，`ctx.connection.fetch.register`，`inject` 含 `connection` 与 `timer`）：

| 路由 | 入参 | 返回 |
|---|---|---|
| `POST /api/clipboard/paste` | `{text, mime?}` | `{ok, name, path, displayPath, bytes, lines, mime, at, hits, reused}` |
| `GET /api/clipboard/list` | `?offset=&limit=` | `{ok, total, totalBytes, offset, limit, hasMore, items[]}`（每项 = 索引条目 + `displayPath`） |
| `GET /api/clipboard/file` | `?name=&head=` | `{ok, item, text, head, lines, trimmed}`（`head` 默认 200 行，最多 64 KiB） |
| `POST /api/clipboard/delete` | `{name}` | `{ok, removed}`（文件已不在也算成功，索引一并清） |
| `GET` + `POST /api/clipboard/config` | `GET` 无参；`POST` `{enabled?, thresholdChars?, thresholdLines?, cleanupEnabled?, cleanupMaxAgeDays?, cleanupMaxTotalBytes?}` | `{ok, limits}`（合并写，只覆盖请求里出现的字段） |
| `POST /api/clipboard/cleanup` | `{maxAgeDays?, maxTotalBytes?}`（缺省用配置值） | `{ok, checked, removed, freedBytes, names[], skipped, maxAgeDays, maxTotalBytes}` |

文件名由服务端按 4.1 生成，不接受自定义 `name`。

错误码：

| code | 状态 | 场景 |
|---|---|---|
| `clipboard/invalid` | 400 | `text` 缺失 / 非字符串 / 全是空白；`name` 非法（含路径分隔符、`..`、以 `.` 开头） |
| `clipboard/not-found` | 404 | 删除 / 预览的文件不在索引与磁盘上 |
| `clipboard/unavailable` | 503 | 数据目录不可写 |

新增组件在 `live-entry-*.js` 里注册 `parts` 一项，`inject` 与其他组件并集合并（含 `timer`，供路由重试使用）。

## 6. 面板与交互

### 6.1 粘贴瞬间

1. 检测命中 → `preventDefault()` 阻止原生粘贴；
2. 调 `POST /api/clipboard/paste`；
3. 成功 → 插入 `@"/Users/x/.dsh/…/143012-a1b2c3d4.txt"`（路径含空白时加引号，否则写 `@路径`）；
   toast「已保存为 143012-a1b2c3d4.txt（2048 行 / 178 KB）」；
4. 失败或超时 → 已 `preventDefault`，改把**原文**插回编辑区（内容不丢），toast 说明原因；
5. 同内容重复粘贴 → 直接用索引里的既有路径，toast 带「复用了已有文件」。

### 6.2 toolkit 分页「剪贴板」

一个分页包含三块：

- **顶部**：`<N> 个文件 · <总大小>`、落点目录（可复制）、「把当前剪贴板转成文件」、
  「立即清理」按钮、刷新；
- **设置区**：「自动转换」开关 + 字符阈值 / 行数阈值；分隔线后是清理三项：
  「自动清理」勾选、保留天数（`0` = 不限）、总量上限（MB，换算成字节，`0` = 不限）；
  按钮文案「保存设置」。改完立即生效 —— 下次粘贴按新阈值判断，清理在下次落盘或刷新时生效
  （同一面板内改，不去设置分页）；
- **列表**：每行 `时间 · 文件名 · mime · N 行 · 大小 · 复用 N 次`，操作为
  `复制 @ 引用` / `复制路径` / `预览` / `删除`（删除前二次确认，删条目同时删文件）；
- 预览是面板内的只读抽屉（前 200 行），不做 modal；空态写明当前阈值与触发条件。

### 6.3 配置落点

`$DSH_HOME/dsh-toolkit/clipboard/config.json`：`{ enabled, thresholdChars, thresholdLines, cleanupEnabled, cleanupMaxAgeDays, cleanupMaxTotalBytes }`，
与 image-gen 的 `config.json` 同构（`0600`、`tmp` + `rename`）。toolkit 的**设置分页**只读展示它
（路径 / 是否存在 / 大小 / mtime），不提供编辑；改配置在剪贴板分页里做。

## 7. 安全与隐私

- 目录 `0700`、文件与索引 `0600`，与 image-gen 的收藏索引一致。
- 粘贴内容可能含 token、内网地址、绝对路径：**本机明文保存**，面板与 toast 明示「不会上传」；不做自动脱敏（脱敏会改变内容，需要时由用户手动处理）。
- 不把正文写进会话记录——只有 `@"路径"` 这段文本进入消息。
- 删除即真删（`unlink`），不回收站；删除入口带二次确认。
- 索引里不冗余保存正文或前 N 行，避免二次泄漏面。

## 9. 已知限制与待验证

| 编号 | 项 | 现状与对策 |
|---|---|---|
| R1 | `@` 引用能否指向 workspace 之外 | 语法层已核实可解析任意路径；模型侧读取受沙箱与审批策略影响。本机 read 可读，若后续受限，在分页里加「复制到工作区」按钮 |
| R2 | composer 编辑区到底是 `contenteditable` 还是 `textarea` | 两者都可能：`textarea` 走 `setRangeText`，`contenteditable` 先 `execCommand('insertText')` 再 `Range` 兜底 |
| R3 | 图片 / 文件粘贴 | 二进制内容不介入，交给 DSH 原生通道；`text/*` 全部识别，只带一种按其格式取扩展名、多种并存统一 `.txt`（见 4.2） |
| R4 | 自动检测读不到剪贴板 | 自动路径只读 `paste` 事件的 `clipboardData`，不需要权限；手动按钮才调用 `navigator.clipboard.readText()` |
| R5 | 代码块 / SQL 里的长文本被顺手转成文件 | 只要命中阈值就转；阈值可在设置里调，另可通过「自动转换」关闭或按 Shift 粘贴（若事件携带 `shiftKey` 则放行原生粘贴） |
| R6 | 与 DSH 未来原生「长文本折叠」冲突 | 本功能可通过「自动转换」开关整体关闭，不修改核心 |
| R7 | 自动清理的「清空全部」 | 只实现「按天数 / 按总量」两条规则，不提供一键清空；逐条删除已够用，整目录删除请手工做（索引下次读列表会自动剔除失效项） |

### 10.2 阈值解析

- 阈值优先级：**环境变量 > `config.json` > 默认**（2000 字符 / 30 行）。正文不设大小上限，也就不需要「单次上限」。
- `GET /api/clipboard/config` 返回的是**已合并环境变量覆盖后的生效阈值**，不是 `config.json` 的原文。

### 10.3 目录与多格式取舍

- `clipboard/` 根目录下除 `index.json` 外还有 `config.json`（内容与权限见 §6.3）；§4.1 的目录树没有画这一项。
- 多份文本格式并存时统一存 `.txt`、内容按 `plain → csv → html` 取第一份，理由：浏览器复制网页就会同时带 `text/plain` 与 `text/html`，宁可丢掉标记，也不要给用户一个半坏的 HTML。

### 10.4 粘贴事件的拦截与放行

- 拦截点：capture 阶段 `document.addEventListener('paste', onPaste, true)`，由 `ctx.effect` 负责移除监听。
- 以下情况放行浏览器原生粘贴（§4.2 只写了其中一部分）：

| # | 放行条件 |
|---|---|
| 1 | 按住 `Shift` |
| 2 | 事件已被别人 `preventDefault()` |
| 3 | 自动转换关闭 |
| 4 | `composer` 上带 `data-clipboard-auto="off"` |
| 5 | 目标不是可编辑元素 |

### 10.5 自检命令与覆盖项

- 自检命令为 `node tools/check-client.mjs`（`npm run check` 是它的包装）。
- 覆盖项：阈值两侧（1999/2000 字符、29/30 行）、`mime` 上报、`@` 引用格式（含空格时加引号）、多份格式取 plain、图片不介入、落盘失败退回原文、去重与 `hits`、文件 `0600` / 目录 `0700`、`list` / `file` 的 head 预览截断 / `delete` / 配置合并写、`name` 穿越与空文本的 400。

### 10.6 已知限制补充

- 只拦 `paste` 事件：拖拽文件、输入法直接输入、命令面板插入的超长文本都不走这里。
- `execCommand('insertText')` 在部分环境已废弃；失败时退回 `Range` 插入，光标停在引用行末尾。
- `@` 引用写的是绝对路径：文件挪走后引用失效；面板里删除条目会同时删文件，两者正好一致。
