# 功能案：工具集壳（components/toolkit）

> 状态：已实现
> 关联组件：`components/toolkit/`（host.js + client.js + README.md）
> 面板位置：侧边栏「工具集」（order 48）
> 同步维护：本文与 `components/toolkit/README.md` 保持一致，改动时请同时更新。

## 1. 要解决的问题

合并前，各业务面板各自往侧边栏登记一行：图片生成（order 49）、模型测试（51）、通知（52）、
MCP（53）、Skill（54），另有一条无标签的 `toolkit-quick` 快捷图标行（并排 A/M/N 三个小图标）；
Token 用量（50）是独立面板。侧边栏被同一个 bundle 撑长，新增功能只能继续往后排，用户要求收成
**一个入口**。

为什么只能合并成「一个长入口」，而不是继续并排：

1. `sidebar.panellist` 是平铺列表，一条 entry 占一行，`order` 只决定先后，没有分组或子菜单。
   要让六个功能只占一行，只能让**一行 entry 打开一个长面板**，在面板内部再分页。
2. 各业务组件仍然必须保留自己的 `main` 面板。每个组件的 `PANEL_KEY`（`image-gen`、`model-test`、
   `notifications`、`mcp`、`skill`、`token-usage`）同时是：
   - `slots.register({ name:'main', key: PANEL_KEY }, Panel)` 里的 **main key**；
   - `ctx.layout.selectPanel(PANEL_KEY)` 的定位键；
   - 单独加载时 `sidebar.panellist` entry 的 `id`。

   工具集壳要把这些面板装进自己的界面，也必须注册一个 `main` 面板；但它**不能复用任何一个业务
   key**，否则该 key 上已登记的面板被顶掉，`ctx.layout.selectPanel('image-gen')` 之类的直达入口
   随之失效；同时壳自己的入口 `layout.selectPanel('toolkit')` 又会找不到面板（`toolkit/client.js`
   的注释专门记了这一点）。两套 key 只能并存——这就是「各组件 main key 冲突」的由来，也是壳固定
   使用 `toolkit` 这个独立 key 的原因。
3. 浏览器侧各组件是彼此独立的工厂，**没有 require 通道**，壳拿不到别人的 `Panel` 函数。解法不是
   让壳 import 业务组件，而是在 bundle 的 `factory(require)` 闭包里放一个共享注册表：组件在
   `apply()` 里调用 `registry.register({ id, Panel, label, order, glyphText })`，壳用
   `registry.entries()` 按 order 拼分页。`build.mjs` 负责把注册表和所有组件工厂放进同一个闭包。
4. 注册表**不能放普通脚本顶层**。HMR 第二次执行同一页脚本时，顶层 `const __dshToolkitRegistry`
   会直接 `SyntaxError: Identifier '__dshToolkitRegistry' has already been declared`，新模块替换
   不掉旧模块，界面停留在旧 bundle——曾经出现「构建产物里已经删掉 `toolkit-quick`，页面还显示
   A/M/N」就是这个问题。放进 `factory` 后，每次 load 都得到独立实例。

## 2. 目标与非目标

### 目标

- 侧边栏只注册一条「工具集」（`id='toolkit'`、`order=48`、glyph `T`），bundle 对侧边栏的贡献
  恒为 1。
- 面板顶部是分页栏，承载五个业务面板 + 壳内置的「设置」；切换分页不经过侧边栏，也不改变
  `layout` 的当前面板。
- 各业务面板保留原 main key 与 `/api/*` Host 路由；`ctx.layout.selectPanel('image-gen')` 等
  直达入口继续有效。
- 「设置」分页只读汇总各组件的数据落点：数据根目录、被环境变量接管的位置、每个组件的目录与
  文件清单（是否存在、大小、mtime），路径可一键复制。
- 分页栏在窄面板下可横向滚动（`overflow-x:auto`），不换行、不折叠。

### 非目标

- 不重写任何业务面板；不代理、不转发它们的 Host 路由。壳只新增一个只读路由。
- 不把 `token-usage` 收进这六页：它仍是独立的隐藏面板（main key `token-usage`，侧边栏不显示）。
- 不做数据迁移、清理、容量统计或配置编辑；设置页只负责「告诉你东西在哪」。
- 不做多 profile 切换、权限控制或远程数据目录浏览。

## 3. 关键约束

| # | 约束 | 依据 | 后果 |
|---|---|---|---|
| C1 | 注册表必须声明在 `factory(require)` 闭包内 | 同页再次执行顶层 `const` 会 `SyntaxError: Identifier '__dshToolkitRegistry' has already been declared`，新 factory 无法替换旧模块 | 每次 load 得到独立注册表；构建产物里只有一个 `__dshToolkitRegistry` 声明 |
| C2 | 业务组件只在 `apply()` 时向注册表登记，不 import 壳 | 浏览器侧没有跨组件 require 通道；组件也要能单独加载 | 组件用 `typeof __dshToolkitRegistry === 'object'` 守卫；注册表缺失时退回自己的侧边栏入口 |
| C3 | 壳必须占用独立 main key `toolkit` | main 槽按 key 区分面板，key 又是 `layout.selectPanel` 的定位键 | 壳与六个业务 key 并存；复用任一业务 key 会顶掉该面板并让 `selectPanel('toolkit')` 抛错 |
| C4 | 五个业务组件的侧边栏入口在 bundle 里不再注册 | 有注册表时组件只调 `registry.register`，`sidebar.panellist` 分支只在单独加载时走 | bundle 的侧边栏 entry 总数为 1，`toolkit-quick` 不再存在 |
| C5 | 「设置」分页不经注册表 | 它是壳的私有 UI，不属于任何 `components/<id>/`，不应被 `build.mjs` 扫描 | `entriesOf()` 末尾硬编码 `{ id:'__toolkit-settings', label:'设置', Panel:SettingsPanel }` |
| C6 | 设置分页 order 固定 9999 | 业务分页是 49–54（50 留给不参与分页的 `token-usage`），将来新增组件也排在它们之后 | 设置页永远最后；分页顺序完全由 order 升序决定 |
| C7 | 壳只提供只读 Host 路由 | 壳不持有数据，写路径属于各业务组件，重复实现会打架 | 唯一路由 `GET /api/toolkit/settings`；无任何写接口 |
| C8 | 路径真值只能引用各组件的解析函数 | 环境变量与 profile 配置会改变落点 | `host.js` import `image-gen/paths.js`、`model-test/presets.js`、`notifications/host.js`；壳不复制第二份路径 |
| C9 | 路由注册要能重试 | 同一 path 重复注册时 DSH 报 `already registered`；HMR/重载时旧路由的 dispose 可能晚于新 apply | `inject` 必须含 `timer`；遇 `already registered` 用 `ctx.timeout(...,400)` 最多重试 10 次 |
| C10 | 单独加载壳或组件都不能露出坏 UI | 开发期会直接 load 单个 `client.js` | 壳在 `slots===undefined || registry===null` 时直接 return，不注册空壳入口 |

**安全与隐私**：设置页只返回**路径、是否存在、字节数、mtime**，不读任何业务文件内容，因此不会带出 API Key、会话正文或提示词。
路径里的 `$DSH_HOME` 已展开成绝对路径（用户要看的就是真实落点），但只是本机路径，不含凭据；路由走
`connection.fetch.register`，鉴权与其余 `/api/*` 一致，没有额外的匿名入口。

## 4. 六个分页与数据来源

分页 = 注册表条目（按 order 升序）+ 壳内置设置页，共六项。

| id | label | order | 来源 |
|---|---|---|---|
| `image-gen` | 图片生成 | 49 | 共享注册表（`components/image-gen/client.js` 的 `apply()`） |
| `model-test` | 模型测试 | 51 | 共享注册表（`components/model-test/client.js`） |
| `notifications` | 通知 | 52 | 共享注册表（`components/notifications/client.js`） |
| `mcp` | MCP | 53 | 共享注册表（`components/mcp/client.js`） |
| `skill` | Skill | 54 | 共享注册表（`components/skill/client.js`） |
| `__toolkit-settings` | 设置 | 9999 | 壳内置（`ToolkitPanel` 同文件的 `SettingsPanel`，`Panel` 直接引用，不经注册表） |

补充：

- `token-usage`（order 50）**不在此表**。它的 `main` key 仍是 `token-usage`，但不上侧边栏、也不
  向注册表登记，因此不出现在分页栏里。
- 注册表条目的 `id` 同时是 React key 和分页选中标识；`glyphText` 只用于单独加载时的侧边栏图标，
  壳内分页栏只显示 `label`。
- 新增一个分页 = 在组件 `apply()` 里 `registry.register(...)`；组件目录由 `build.mjs` 自动发现，
  壳不用改。

## 5. 接口契约

### `GET /api/toolkit/settings`

- 无参数、只读，响应 `cache-control: no-store`。
- 成功 `200`：

```jsonc
{
  "ok": true,
  "version": "0.2.0",                       // 读根 package.json 的 version
  "dataDir": "~/.dsh/dsh-toolkit",          // 响应里已是展开 ~ 的绝对路径（此处示例用 ~）
  "overridden": {
    "data": true, "images": false, "config": false, "library": false,
    "usage": false, "prompts": false, "favorites": false, "pricing": false
  },
  "overriddenNames": ["data"],              // overridden 中值为 true 的键
  "components": [
    {
      "id": "image-gen",
      "label": "图片生成",
      "dir": "~/.dsh/dsh-toolkit/image-gen",
      "files": [
        {
          "label": "生成图目录",
          "path": "~/.dsh/dsh-toolkit/image-gen/images",
          "kind": "dir",                    // 'dir' | 'file'
          "exists": true,
          "bytes": 0,                       // dir 恒为 0
          "mtime": 1700000000000            // mtimeMs；不存在为 0
        }
      ],
      "total": 1,                           // files 中 exists=true 的条数
      "bytes": 0                            // files 的 bytes 之和
    }
    // …其余组件块
  ]
}
```

- 失败 `500`：`{ ok:false, code:'toolkit/settings-failed', message }`。
- `overridden` 的键固定为 `data / images / config / library / usage / prompts / favorites / pricing`，
  由 `image-gen/paths.js` 的 `resolvePaths()` 给出；壳只做透传，不自行推断环境变量。
- 存在性用 `statSync` 判定：路径不存在或不可读一律 `exists:false`，不抛错。文件给 `size`，目录给
  `bytes:0`，两者都给 `mtimeMs`。

### 组件块固定顺序

`components[]` 的顺序在 `host.js` 的 `storageOverview()` 里写死，**不是**按分页 order 排：

| # | id | label | dir | 文件项 |
|---|---|---|---|---|
| 1 | `image-gen` | 图片生成 | `imageGenDir()` | 生成图目录（dir）、模型目录、提示词库、图片提示词索引、收藏索引、生图计费记录，共 6 项 |
| 2 | `token-usage` | Token 用量 | `tokenUsageDir()` | 价目文件，1 项 |
| 3 | `model-test` | 模型测试 | `modelTestDir()` | 参数覆盖、models.dev 预设，2 项 |
| 4 | `notifications` | 通知 | `notificationsDir()` | 通知配置、通知队列，2 项 |
| 5 | `mcp` | MCP 管理 | `null` | 空；`note` 说明条目写进当前 profile 的 `cordis.patch.yml`，不占数据目录 |
| 6 | `skill` | Skill 管理 | `null` | 空；`note` 说明读写 profile 里的 skills 目录，不占数据目录 |

`tools/check-client.mjs` 第 4.4 节把这个顺序当契约断言，增删组件块必须同步修改 host.js 与该断言。

## 6. 卸载与状态

- 壳只持有一份极小的共享状态：`registry.shell = { active: '', listeners: Set }`，`active` 是当前
  分页 id。它挂在注册表上，不写 localStorage、不写 Host，刷新或换 bundle 后从 `''` 开始。
- `ToolkitPanel` 每次只 `React.createElement(activeEntry.Panel)`，**非活动分页整个卸载**（源码注释：
  「避免后台轮询常驻」）。切走再切回是重新挂载：分页内部的本地 state 会重置，未保存的表单内容
  可能丢失；切页动作本身不会触发业务面板自己的「未保存改动」确认。
- 切页通过 `selectTab(key)` 写 `state.active` 再 `emit()`，订阅者（`ToolkitPanel` 的
  `useEffect`）重渲染；订阅在组件卸载时从 `Set` 里删除。`currentTab()` 找不到 active 时回退到
  第一个可用分页，所以默认页是图片生成。
- 「设置」页自己不缓存数据：挂载时 `fetchJson('/api/toolkit/settings')`，点「刷新」重新请求；失败
  显示「读取数据目录失败：…」。
- **通知轮询不属于分页生命周期**。`notifications` 插件的 `apply()` 里用 `ctx.interval(refresh, 8000)`
  起轮询并做系统投递，和 React 分页是否挂载无关；切到别的分页后仍会收到系统通知。这也是壳不能
  靠「卸载页面」来停业务后台任务的原因——停不停由各插件自己决定。

## 7. 验收标准

命令（不在本文执行，由维护者跑）：

```bash
node --check components/toolkit/host.js
node --check components/toolkit/client.js
node build.mjs && node tools/check-client.mjs
```

`tools/check-client.mjs` 外壳段（约 1318–1345 行）断言：

1. `panelOf('toolkit')` 与 `glyphOf('toolkit')` 都存在，label 为「工具集」，order 为 48。
2. `glyphOf('toolkit-quick') === undefined`；`image-gen / model-test / notifications / mcp / skill`
   五个业务组件的 `glyphOf` 全部为 `undefined`。
3. `sidebar.panellist` 的注册总数为 1。
4. 渲染 `ToolkitPanel` 后，文本里能依次找到「图片生成」「模型测试」「通知」「MCP」「Skill」，
   且默认内容是图片生成（含「左栏收纳」文案）。注意：该段**不**断言「设置」标签，见第 8 节。

第 4.4 节（约 3361–3408 行）断言：

1. `components/toolkit/host.js` 的 `inject` 含 `timer`。
2. 注册了 `GET /api/toolkit/settings`，请求返回 `200 { ok:true }`。
3. `body.dataDir` 等于 `DSH_TOOLKIT_DATA` 指向的沙箱目录，`body.version === '0.2.0'`。
4. `components` 的 id 顺序严格为 `image-gen / token-usage / model-test / notifications / mcp / skill`。
5. `image-gen.files.length === 6`，包含 `favorites.json` 与 `kind:'dir'` 的 `images`；存在性按磁盘
   回报（沙箱里写了 `config.json` 为 true，`library.json` 为 false）。
6. `mcp.dir === null` 且 `mcp.note` 是字符串。
7. `overriddenNames` 包含 `'data'`（`DSH_TOOLKIT_DATA` 接管）。
8. 构建产物根 `client.js` 同时含 `__toolkit-settings` 与 `/api/toolkit/settings`。

手工复核（Client Inspect）：`Slots.listSubTree` 里 `sidebar.panellist` 只有 `toolkit` 一条；
`main` 有五个业务面板 + `token-usage` + `toolkit`。

## 8. 已知限制

- **分页不可深链、不记忆**：`ctx.layout.selectPanel('toolkit')` 只能打开壳，不能指定分页；刷新、
  重载 bundle 后回到第一页（图片生成）。没有 URL 路由或持久化。
- **切页会丢未保存内容**：非活动页整个卸载，业务面板来不及拦截；壳不做跨页草稿。
- **设置页只读**：不能改环境变量、不能迁移/清理数据、不能打开目录；显示的是当前进程解析出的
  路径，改了环境变量要重载插件。
- **组件块顺序与文件项是硬编码**：新增/改名/删除组件时，必须同步 `components/toolkit/host.js`
  与 `tools/check-client.mjs` 第 4.4 节，否则自检失败；设置页不会自动发现新组件的数据。
- **只显示已注册的面板**：组件没在 `apply()` 里 `registry.register`，或构建产物没重新生成，分页栏
  就少一项（甚至显示 `EMPTY_HINT`）；壳不会从 Host 侧反推面板。
- **`token-usage` 不在分页里**：它仍是独立面板，只能通过 `layout.selectPanel('token-usage')` 或
  它自己的入口打开，设置页里却仍会列出它的价目文件。
- **窄面板只做横向滚动**：分页栏不折叠成下拉，分页很多时会需要横向拖动。
- **「设置」标签未被自检直接断言**：现有外壳段只断言五个业务标签与默认内容；「设置」只由 4.4 节
  对 `client.js` 文本的 `__toolkit-settings` 断言间接覆盖。
- **路由重试只认 `already registered`**：其它注册异常会被吞掉并放弃，不冒泡到 UI；排查时要看
  Host 日志。
